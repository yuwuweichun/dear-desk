## 1. 所有权与挂载

`src/scene/DeskScene.tsx` 的 `DeskContents` 将 `StudyRoomShell` 作为现有桌面对象的同一 R3F Canvas 兄弟对象挂载。`StudyRoomShell` 负责生命周期和挂载，不拥有桌面、日记、贴纸或持久化状态；房间表面全部禁用射线，因此不会改变既有交互命中语义。

调用链为：

```text
DeskContents -> StudyRoomShell -> createStudyRoomShellModel
             -> STUDY_ROOM_MODEL_SPEC -> room geometry/materials/runtime
```

桌面首页的 `ProductApp` 持有会话内 `showRoomBackground`（默认 `true`），经 `DeskScene` 传入 `DeskContents`。该值为 `false` 时不挂载 `StudyRoomShell`，为 `true` 时恢复挂载并由组件重新创建模型；它不进入 Zustand、IndexedDB 或 renderer 背景色。

## 2. 坐标与几何事实

`STUDY_ROOM_MODEL_SPEC` 是房间尺寸、窗口开口和装饰尺寸的单一规格来源。当前室内尺寸为 `42 × 33 × 18`，地板顶面固定为 `y=-5.025`，墙顶为 `y=12.975`；因此桌腿底面 `y=-5.02` 与地板保持 `0.005` 的既有接地差。

房间由 38 块浅盒木板及暗色底层、四面内向墙和四个墙角封边柱组成，顶部保持开放。北墙拆成窗洞左右、上下四块墙板；窗口是六段外框、中央横竖梃、四块玻璃、向室内突出的窗台、窗台下裙板、户外隔离底板和真实墙体开口的组合。窗洞当前宽 `10.3`、高 `12.65`，中心位于北墙中心线 `x=0`；窗台深 `1.05`、高 `0.22`，额外外伸 `0.68`。桌子正面朝 `+Z`，北墙位于桌子后方并作为正面视角中的前方墙面。四条踢脚线使用一个八实例网格：每边一个主板和一个顶部压条，主板高 `0.94`、深 `0.26`，压条高 `0.12`。墙体、地板、窗台、裙板、窗框、玻璃和踢脚线均禁用 raycast，墙角封边只负责阻断零厚度墙面交接处的背景漏出。

产品 `front` 固定机位由 `src/scene/DeskScene.tsx` 的 `getCameraPoses()` 提供：桌面端使用位置 `[0.15, 5.5, 15.2]`、目标 `[0, 2.5, 0.15]`、`fov=44`；移动端使用位置 `[0.1, 6.5, 16.2]`、目标 `[0, 3.5, 0.15]`、`fov=46`，以桌面上方的俯视机位同时覆盖桌面和北墙窗户，并避免朝向开顶。`far` 与 `near` 机位保持独立。

## 3. 材质与资源生命周期

房间工厂为每次模型实例创建私有的墙面、地板、板缝、窗框、踢脚线、玻璃和户外底板材质，并登记 5 张私有程序纹理。墙面四个方向共享同一个墙面材质和同一套颜色/纹理；不同视角的亮度差来自光照和法线，不按墙面方向额外染色。墙面材质使用 `THREE.DoubleSide`，墙体接收阴影但不投射阴影，避免零厚度大墙面在地板上形成覆盖整个房间的伪影。

墙面与地板使用 `512 × 512` 程序纹理。albedo 使用 `THREE.SRGBColorSpace`；roughness、height/bump 与 AO 数据使用 `THREE.NoColorSpace`。墙面 albedo 的基础采样约为 `rgb(137,146,126)`，材质本身保持白色以避免颜色二次相乘，并使用低强度 `emissive` 基础色抵消不同墙面法线面对方向光时产生的过大明暗差；表面叠加低频斑驳与微起伏。地板使用 38 块偏窄、沿房间纵深连续排列的 `InstancedMesh` 木板；每块木板具有轻微实例颜色差，纹理提供纵向 grain、波纹、结疤和 roughness/bump，暗色底层从 `0.04` 宽的几何间隙露出。窗框为偏暖米色 `#d1bd97`，踢脚线为 `#cbb991`。

工厂在 `root.userData.dispose` 中释放所有自有几何、材质和纹理。runtime 同时登记地板 collider、窗口/玻璃 destruction groups、命名节点和资源指标，供既有模型评审与资源测试使用。

窗台、裙板和地板实例增加了结构读数；房间专属测试将 draw-call 上限保持为 `29`，全局模型预算仍由既有 `MODEL_LIMITS` 约束。

开发环境支持 `?review=room&view=concept-perspective` 和 `?review=room&view=opposite-corner` 两个固定审查机位。它复用现有 `ModelReviewScene` 和同一个 R3F Canvas，仅用于截图与多角度结构检查，不进入产品交互或持久化模型。

## 4. 边界

房间壳体是桌面的非交互视觉背景，不提供自由走动、家具装修、灯光控制或房间持久化状态。renderer 的清屏背景仍不是实体，也不提供碰撞或遮挡；开放顶部允许从朝上视线看到清屏背景。桌子及其交互对象继续使用原世界坐标；本次扩大壳体不修改桌面数据、IndexedDB 或 Canvas 数量。

场景不再创建 `THREE.Fog`。渲染相机远裁剪面为 `100`，覆盖 `42 × 33 × 18` 房间的对角墙角；移除雾后，墙面可见性只由几何、材质、法线、相机裁剪范围和现有灯光决定，背景色不会通过深度雾或远裁剪缺口覆盖远墙。
