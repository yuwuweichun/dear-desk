Dear Desk · 当前事实架构

写下的内容怎样留在本地，又怎样变成桌面上的一本日记？

你看到的是一张可以打开本子、写日记和摆贴纸的桌面。文字和贴纸先保存在当前浏览器里，页面状态只负责协调当下操作，桌面与纸页再把同一份内容画出来；因此动画可以变化，已经保存的记录不会跟着模型消失。

当前事实

当前应用已经能打开本子、阅读和书写日期页面、制作贴纸并把它们留在桌面或日记中。本子打开时长边书脊始终贴着桌面，书口先向上立起，再让左右两半从书脊向两侧摊开；旧的连续快速扫页已经移除。所有内容仍只保存在当前浏览器，三维物体和动画只是可随时重建的画面。

01 · 心智模型

保存的内容、当前操作和眼前画面各有自己的责任

可以把它理解成三层：浏览器里的资料柜保存文字和贴纸；页面里的值班员记住现在打开哪一天、正在做什么；桌面、本子和表单只负责把结果呈现出来。源码把资料柜实现为浏览器数据库 IndexedDB，把值班员实现为页面状态 Zustand store，再由普通页面元素和三维场景共同显示。纸张角度、模型节点和临时图片地址都不是已保存的日记内容。

02 · 运行时

React 组合一个 store，并保证 WebGL Canvas 单活跃

src/main.tsx 创建两个 Dexie repository 和一个 Zustand store，并依次载入 animal-island-ui/style、应用样式和 Dear Desk 主题覆盖。App 根据 stickerWorkflow 切换桌面与制作器：composing 时卸载 R3F，再让 Sticker Forge 创建自己的 Canvas；其他阶段由 DeskScene 持有唯一 R3F Canvas。双页日记始终是 Canvas 的 DOM sibling。

当前运行时层级
main.tsx
└── AppStoreProvider
    └── App
        ├── stickerWorkflow === 'composing'
        │   └── StickerStudio -> one Sticker Forge Canvas
        └── otherwise
            ├── DeskScene -> one R3F Canvas
            │   ├── CameraRig + SceneEnvironment
            │   ├── createDeskModel + createDeskMatModel
            │   ├── independent desk-mat placement hit surface
            │   ├── NotebookObject -> createNotebookModel
            │   └── StickerObject[] for desk surface
            ├── JournalPanel -> DOM double-page book
            │   ├── BlankJournalPage -> previous-page intent
            │   ├── JournalReadingPage -> current right-page text + stickers
            │   ├── one vertical reading/editing slider + writing/font actions
            │   └── PageTurnSheet -> CSS 3D animation
            └── StickerControls
CSS 3D 不是第二个 WebGL renderer

PageTurnSheet 只使用 DOM 的 perspective、rotateY、正反面和阴影。它没有 Three.js scene、Canvas 或持久化物理状态；reduced-motion 下改为短淡出。

03 · 场景模型

可序列化规格生成 Three.js 运行对象，React 只协调生命周期

DeskScene 创建一份 createModelMaterialLibrary，再把它交给 createDeskModel、createDeskMatModel 和 createNotebookModel。三个工厂都返回 plain Three.js Group；根节点的 userData.sculptRuntime 暴露命名节点、socket 与 collider，书写桌还发布三只抽屉的线性 action、attachment binding 和附件更新入口，供交互包装层使用，但这些运行对象不会进入 Zustand 或 IndexedDB，当前产品也没有开放抽屉操作。

模型创建、动作与释放调用链
DeskScene
  -> createModelMaterialLibrary()        // shared 1024px PBR channels
  -> createDeskModel(materials)
  -> createDeskMatModel(materials)
  -> NotebookObject
       -> createNotebookModel(materials)
       -> userData.setOpenProgress(t)    // rise -> center spread -> settle
  -> unmount
       -> model.userData.dispose()       // factory-owned geometry
       -> materials.dispose()            // shared material + 16 textures
       -> SceneEnvironment cleanup       // PMREM + RoomEnvironment

本子工厂保留稳定根位置、透明命中盒和封面铰链；所有可见部件现在统一挂在中央展示锚点 centered-opening-presentation 下。它内部的桌面书脊铰链 tabletop-spine-hinge 位于长边装订轴，立起时绕这条轴旋转，轴本身不离开桌面；书口因此向上，而不是让整块封面朝镜头抬起。getNotebookPresentationState 先把进度映射为立起，再映射为左右摊开和落定。展开阶段的公共书脊角度严格使用 1 - spreadProgress：右半册世界角度从 π/2 到 0，左半册在相同公共角度上叠加 π × spreadProgress，因此任意时刻两侧离开直立位置的角位移绝对值相同。展示锚点同时补偿书脊横向位置，所以直立书脊和最终页芯中心共享桌面中线。完全闭合与书脊贴桌立起时，单一 continuous-case-shell 网格负责前封面、连续圆背和后封面；装饰性的 book-joints 已删除。spreadProgress 一旦大于零，连续壳体就退出，front-cover-board 与 back-cover-board 同帧接替；两块封面的中线补偿从 0 随展开进度连续插值到各自的 0.2，所以闭合圆背端部不会在纸面中线冒出，也不会在动画末端跳变。setOpenProgress 同时更新两侧页堆、书脊倾角和中心补偿；全开末段把左页 pivot 降到右页高度并精确转到 π。动画阶段的左右独立顶页在全开后退出，不再创建或显示额外的连续顶层纸面；左右页堆和各自页口层直接作为 3D 打开终态。旧的 rapid-page-flip-pool 也已删除，不再用临时页片从第一页连续扫页。NotebookObject 只传入既有状态机进度；关闭沿同一时间轴逆放。notebookPhase === 'editing' 时隐藏 3D 本子并挂载 DOM 日记，development 与 production 使用同一交接行为。

桌垫的可见织物模型与透明 placement hit surface 分离，所以材质和滚边几何不承担贴纸事件。重复织线、页缘、页线与铆钉使用实例化几何；材质库以确定性 1024px 程序纹理为 wood、cloth、kraft、paper 四个 family 各提供 albedo、AO、height 和 roughness，共 16 张纹理。当前 SCENE_MATERIAL_VERSION 为 V2.0；SCENE_PALETTE_PRESETS 保存已全部否决的 V1-V10 历史角色色，默认 SCENE_PALETTE 仍解析为运行回退值 V2。开发环境可用 ?palette=v1..v10 决定调色器初始值，production 和无效参数均回到 V2；该选择与实时试色都不进入 store、IndexedDB 或 localStorage。

ProductApp 以组件级 SceneColorConfig 持有九项临时 HEX，并把它传给 SceneColorEditor 与 DeskScene。材质库只创建一次 16 张程序纹理；后续输入通过 applySceneColors() 原位更新九个材质颜色，背景/fog 由 R3F prop 同步，不重建纹理、相机或 Canvas。桌面、桌框与围板、收分桌腿、抽屉面、桌垫工作面、垫体/包边、本子外壳和书脊/接缝各有明确材质所有权；抽屉面从 deskInset 派生较深木色，纸张、贴纸、PBR 与灯光不进入调色配置。

04 · 双页日记

日期索引确定右页，局部会话再控制阅读、书写与保存

  1. 加载今天App 调用 loadToday() 和 loadStickers()，保持桌面摘要、当天编辑和贴纸目标兼容。
  2. 打开本子3D 命中区或 DOM 按钮把 NotebookPhase 推进到 editing；此时统一挂载 JournalPanel 并以 reading + idle 开始，同时隐藏 3D 本子。
  3. 建立页序loadJournalPages() 并行读取 DailyEntryRepository.listDates() 与 StickerRepository.listJournalDates()，合并今天、去重、排序并丢弃未来日期。
  4. 按需读取首次读取当前右页日期的正文与贴纸 Blob；页序查询本身只读取日期/instance 字段，不加载全部历史 PNG。
  5. 呈现当前日期journalCursor 只代表右页日期。左页展示同一日期的贴纸并提供“前往贴纸工作台”入口；右页统一投影今天或历史正文。
  6. 进入书写外置的单个竖向滑动按钮按“阅 / 读 / 编 / 辑”自上而下显示，选中块随 journalMode 上下移动；切到编辑会直接以当前右页标题和正文初始化 draftDate、draftTitle 与 draft，切换为标题输入和 textarea 并聚焦；收笔成功后回到 editing + idle，再次点击书写只恢复同一页已保存值；书写阶段动作变为“图标 / 收 / 笔”。
  7. 选择字体编辑模式在书写动作下方显示字体入口。JournalBook 从 localStorage 读取稳定字体 ID，并用 data-journal-font 同时控制 textarea 与只读正文；切换字体不改写 DailyEntry 纯文本。生产环境提供纸页宋体、玄冬楷书和随峰体，开发环境额外允许云峰晶晶体。
  8. 按页保存“收笔”调用 saveJournalEntry(rightDate, draft, draftTitle)。repository 仍按显式日期写入标题和正文；store 更新 journalPageEntries[date]，仅当日期是今天时同步 entry 别名。
  9. 保护草稿标题或正文有改动时，翻页、切回阅读和关闭只显示“请先收笔”，不会提交游标、关闭本子或自动写库；标题/正文任一校验或保存失败都继续保留两个草稿。
  10. 请求翻页双页下方的上一页/下一页按钮调用 requestJournalTurn('previous' | 'next')。页面本体不再承担整页翻页命中；书写中由组件拦截，边界或 store 非 idle 请求返回 false。
  11. 预读并提交store 补齐目标右页缺少的正文和贴纸，再把阶段从 loading 切到 turning；PageTurnSheet 动画结束后调用 settleJournalTurn() 原子提交游标。
  12. 保持今天selectedDate 始终是今天，仍只决定贴纸工作台“放到日记”的目标；历史正文可编辑不会改变该贴纸 placement 语义。
翻页状态协议
idle
  -> requestJournalTurn(direction)
  -> loading: read target right page and previous neighbor if cache misses
  -> turning: render PageTurnSheet and lock new intents
  -> CSS animationend
  -> settleJournalTurn()
  -> commit journalCursor
  -> idle
局部阅读与书写协议
reading + idle
  -> editing + writing (draftDate/title/text = current rightDate)
  -> editing + saving
  -> saveJournalEntry(rightDate, draft, draftTitle)
  -> editing + idle (success) | editing + writing (failure)

05 · 贴纸

制作器独立于日记草稿，结果可以落到桌面或今天

桌面“贴纸工作台”进入 composing 后，StickerStudio 支持文字、PNG/JPEG/WebP、矩形保留、本地 U-2-Netp 自动抠图和 Canvas 2D 手动修整。Sticker Forge 仍只负责公开 source 的轮廓、材质、peel 预览与 flat PNG 捕获。

贴纸调用方向
App.openStickerStudio()
  -> App unmounts DeskScene
  -> StickerStudio + optional local cutout worker
  -> fixed Sticker Forge session
  -> transparent flat PNG + confirmed source PNG
  -> prepareStickerPlacement(draft, 'desk' | 'journal')
  -> one Dexie transaction writes source/definition/render/instance
  -> desk: StickerObject (R3F)
  -> journal: JournalStickerLayer (DOM, selectedDate = today)

日记历史贴纸只投影，不允许选择或拖动；历史正文则通过统一的“编辑 → 书写 → 收笔”流程修改。当前日期左页支持贴纸放置、移动、15° 旋转和删除；工作台入口会先退出本子并让 Sticker Forge 接管唯一制作 Canvas。上一页/下一页按钮独立于纸面，避免覆盖正文选择和 textarea。

07 · 数据

IndexedDB v4 保存业务内容，localStorage 只保存轻量字体偏好

数据库名为 dear-desk。v3 保留 dailyEntries，新增图片 source 表，并让实例使用 desk | journal 判别联合；日记实例通过 [surface+journalDate] 索引按日期查询。v4 新增单例的 notebookCoverSettings 表保存本子铭牌文字。dailyEntries 现在写入标题与正文；旧版本记录没有标题字段时由日记投影按今天/历史页回退。阅读/书写模式、标题/正文草稿、游标仍不持久化。

字体选择不是日记内容。journal-font.ts 使用键 dear-desk:journal-font 在 localStorage 保存 paper | jingjing | xuandong | suifeng；读取时同时检查值是否合法、当前构建是否允许，并在存储不可用或值不受支持时回退 paper。因此既有正文无需迁移，生产环境也不会因为开发偏好指向 jingjing 而请求未发布资源。

IndexedDB v4 schema
database.version(4).stores({
  dailyEntries: 'date, updatedAt',
  stickerDefinitions: 'id, kind, createdAt',
  stickerInstances: 'id, surface, [surface+journalDate], definitionId, updatedAt',
  stickerRenderAssets: 'id, upstreamCommit',
  stickerSourceAssets: 'id, createdAt',
  notebookCoverSettings: 'id, updatedAt'
})

同时是正文主键和日记贴纸关联键； 让 DOM 与 R3F 可以从同一 PNG 事实重建视觉。清除站点数据、换浏览器或换设备会失去这些内容，这是当前边界。

08 · 渲染

R3F 给出空间本子，DOM 适配层保持表单语义

NotebookObject 用透明命中几何发出打开意图，并驱动 createNotebookModel 的中央展示锚点、封面铰链和左右页堆；它不读取正文或 Blob。桌面端与移动端 near 机位已放宽视野，竖起轮廓不会撞到上边界。JournalPanel 在打开进度完成、notebookPhase 进入 editing 后接管，提供当前日期贴纸左页、正文右页、独立翻页控制、局部模式控件和按日期 textarea；开发和生产使用相同的 3D 隐藏与 DOM 挂载行为。旧 RoundedBox / scene-visuals 已不在当前桌子、桌垫、本子模型路径中。

renderer 使用 ACES filmic tone mapping、显式曝光、PCF 阴影和 DPR [1, 1.5]；SceneEnvironment 生成并释放 PMREM 环境反射。场景只有一盏投影方向光，另有不投影的低强度补光；雾从主体之外开始，避免吞掉桌体层次。

JournalStickerLayer 的坐标是纸页内 0..1 归一化值。今天页保留 pointer capture、预览位置和 pointer up 提交；历史页即使进入正文书写也只复用 PNG 投影并关闭贴纸 pointer events。桌面 StickerObject 仍创建对象 URL 和 Three.js Texture，并在卸载时释放两者。

日记字体通过 .journal-panel 上的 data-journal-font 映射到共享 CSS 变量 --journal-writing-font，因此阅读正文和 textarea 使用同一套字体栈。玄冬楷书和随峰体来自 public/fonts/ 的生产公共资源，其中随峰体为 cjkFonts 官方 The Peak Font Plus V1.002，许可证与来源哈希记录在同目录；云峰晶晶体只在开发模式由 vite.config.ts 的 development-font-assets 中间件从 dev-assets/fonts/ 响应，并由组件在开发模式注入对应 @font-face。该中间件只应用于 serve，生产构建不会复制或引用云峰晶晶体。

src/ui/ 是业务交互控件与 animal-island-ui@1.5.1 之间的适配边界：Button 将 loading 映射为原生 disabled，IconButton 固化可访问名称，TextInput 和 SegmentedControl 统一输入与选择语义。第二轮重写删除了让组件回到旧式深色小圆角外观的覆盖，theme.css 现在保留库的胶囊、按压阴影、Nunito/Noto Sans、青绿 active 与暖白 surface，只补 Dear Desk 的业务色彩和领域布局。App、Journal 和 Sticker 的交互控件从该层导入；ProductApp 对无需业务语义适配的纯展示型 Time 直接传入 type="hud"。领域专用 textarea、文件输入、颜色 swatch、range、纸页命中区、Forge mount 与抠图 Canvas 不进入通用组件库。

StickerStudio 的页面骨架仍由业务组件拥有，但 src/styles.css 和 src/sticker-workbench.css 已把旧胡桃木/深苔网格背景、窄纸侧栏和方形控件整体替换为浅薄荷点阵制作空间、暖白预览框、圆角点阵控制面板、青绿来源/材质选择与青绿/珊瑚双目标动作。Forge Canvas、来源更新、抠图 session、capture 和 placement action 没有变化。

ProductApp 不再渲染 app-header、品牌链接或“本地”常驻状态。DeskScene Canvas、StickerStudio 和 scene fallback 都从视口 y=0 开始；左上角只在桌面 idle 阶段挂载 animal-island-ui 的 Time type="hud"，按浏览器本地时间显示英文星期、英文月日与 24 小时时间。旧的所选日记日期以及“今天还是空白 / 今天有一页”等记录状态不再由桌面 HUD 呈现；loadToday() 仍照常执行并服务日记链路。该视觉替换没有改变本地持久化事实，“本地”仍是 IndexedDB 架构边界而不是需要持续显示的运行状态。

为什么正文不进入 WebGL

textarea、键盘焦点、选择文本、错误反馈和屏幕阅读器语义都更适合 DOM。只有相机、光照、遮挡和桌面空间坐标进入 R3F；仿真翻页的视觉价值不需要牺牲表单质量。

09 · 失败路径

加载、翻页、保存和制作失败都保留上一份可靠事实

失败点当前行为保留内容
今天读取失败loadStatus: error，显示本地记录不可用数据库不被改写
历史日期索引或可见页读取失败journalLoadStatus: error，双页显示可见错误今天正文和贴纸链路仍独立
目标页预读失败翻页从 loading 复位到 idle，不提交游标原跨页保持不变
快速重复点击非 idle 请求返回 false只有一个 pending cursor
dirty 书写时翻页、切回阅读或关闭意图被组件拦截，live status 提示先收笔当前右页、模式与局部草稿

贴纸移动提交失败显示错误并重新加载持久化位置最后一次成功位置

10 · 示例

正文页、贴纸-only 页和今天怎样组成一本本子

假设 IndexedDB 中有 8 月 5 日正文、8 月 7 日只有一张日记贴纸，而今天是 8 月 9 日且尚未保存。日期查询合并后得到三个页面，不生成 8 月 6 日或 8 月 8 日的无限空白纸。

页面序列与一次向前翻
journalPageDates = [2026-08-05, 2026-08-07, 2026-08-09]

open (reading):
  left  = blank (previous-page hit target -> 2026-08-07)
  right = 2026-08-09 (today text + stickers)

click left:
  preload 2026-08-05
  animate left sheet toward right
  settle cursor

result:
  left  = blank (previous-page hit target -> 2026-08-05)
  right = 2026-08-07 (sticker-only, right edge -> next)

edit historical text:
  click 编辑 -> 书写 -> textarea for 2026-08-07
  click 收笔 -> saveJournalEntry('2026-08-07', draft)

顶层编辑模式可以跨翻页保持；切到编辑即为当前右页创建标题和正文草稿，收笔后可再次点击“书写”恢复同一页已保存值。只有“收笔”成功才写 dailyEntries；标题或正文 dirty 草稿会阻止关闭，页面刷新仍不提供未保存草稿恢复。关闭并重新打开后，阅读游标和模式回到今天的阅读态。
