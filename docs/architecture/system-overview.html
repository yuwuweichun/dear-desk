Dear Desk · 当前事实架构

本地记录与贴纸，投影到 DOM 和单活跃 WebGL 画布

当前应用是一个纯前端、本地优先的单页应用。IndexedDB v2 保存当天文字、贴纸定义、透明 PNG 与桌面实例，Zustand 协调本子和贴纸工作流；DOM 承担编辑与控制，WebGL 在桌面 R3F 与 Sticker Forge 制作器之间切换所有者。

当前实现边界

编号 002 与 003 已形成当天记录和本子转场链路；编号 007 已实现固定版本 Sticker Forge 的文字贴纸制作、放置、移动、旋转、删除与重开恢复。图片贴纸、台灯、过去日期和云同步仍未接入。

01 · 心智模型

先分清事实、协调与投影

系统没有服务端。用户保存后，浏览器当前 origin 下的 IndexedDB 成为持久化事实；页面内的 Zustand store 是一次运行期间的协调层；DOM、Sticker Forge 制作器和 R3F 桌面都是状态的消费者或临时视觉生产者。

01用户意图记录、制作或摆放贴纸
02应用动作Zustand 协调异步状态
03领域与仓储校验并事务读写记录与贴纸
04IndexedDB保存当前浏览器事实
05视觉投影DOM、Sticker Forge 或 R3F

描述数据边界； 描述 Three.js 的责任。两者共同保证撤掉 3D 场景时，日记数据仍然可以独立读取。

02 · 运行时

React 保证任意时刻只有一个 Canvas 所有者

src/main.tsx 创建日记与贴纸 repository，再把同一个 Zustand store 注入 React 树。App 根据 stickerWorkflow 条件装载桌面或制作器：idle/placing 使用 R3F，composing 卸载 R3F 后才让 Sticker Forge 创建自己的 renderer。

当前运行时层级
main.tsx
└── AppStoreProvider
    └── App
        ├── stickerWorkflow === 'composing'
        │   └── StickerStudio -> Sticker Forge Canvas
        └── otherwise
            └── DeskScene -> one R3F Canvas
                ├── camera + lights + desk + NotebookObject
                └── StickerObject[] from persisted PNG Blobs

DOM siblings: header, JournalPanel, StickerControls
单活跃 Canvas，不是单一 renderer 类型

Sticker Forge 的公开 API 拥有自己的 renderer，不能直接复用 R3F root。因此系统切换所有者，而不是同时挂载两张 Canvas。制作器卸载时幂等调用 destroy()；桌面再从持久化 PNG 恢复贴纸视觉。

03 · 主链路

日记提供文字，Sticker Forge 生成可持久化视觉

  1. 启动加载App 挂载后调用 loadToday()，store 以浏览器本地日期向 repository 查询。
  2. 请求打开3D 命中区域或 DOM 等价按钮调用同一个 requestNotebookOpen()，把阶段从 desk 推进到 approaching；重复和越序请求无效。
  3. 完成转场CameraRig 插值 position、Quaternion 与 FOV，随后 NotebookObject 绕书脊展开上封面；只有进入 editing 后 JournalPanel 才挂载并聚焦 textarea。
  4. 保留草稿未保存文字只存在于 JournalEditor 局部 state，不会在每次按键时写数据库。
  5. 显式保存saveEntry(text) 调用 repository；领域函数先去除首尾空白并校验 1 到 500 个字符。
  6. 事务提交Dexie 在一个读写事务中读取旧记录并执行 put，更新时保留 createdAt。
  7. 进入制作“制作贴纸”规范化最多 60 个字符，把未保存草稿暂存到 store，并把工作流切到 composing；取消制作会返回编辑态并恢复草稿。
  8. 真实渲染StickerStudio 动态加载固定 commit 的官方 ES bundle，调用 createSticker()，再通过公开 API 更新文字、颜色、材质与 peel 预览。
  9. 确认快照确认时先 reset() 并等待 ready、非 dragging、progress 归零；读取上游 Canvas，按 alpha bounds 裁切为透明 PNG Blob，然后销毁 Forge。
  10. 放置提交R3F 桌面恢复后，用户点击桌垫；repository 在一个 Dexie 事务中写入 definition、render asset 和 instance，放置点由领域层限制在桌垫范围内。
  11. 桌面编辑与恢复拖动过程只更新 store，pointer up 才写位置；旋转每次 15°，删除同事务清理三条记录。页面重开加载 Blob、坐标和方向，创建临时对象 URL 与 Texture 投影。
贴纸调用方向
JournalPanel draft
  -> appStore.startStickerComposer(text)
  -> App unmounts DeskScene
  -> StickerStudio -> createStickerForgeSession()
  -> vendored Sticker Forge createSticker()
  -> reset + flat wait + transparent PNG crop
  -> appStore.prepareStickerPlacement(draft)
  -> App remounts DeskScene
  -> desk raycast -> appStore.placePendingSticker(position)
  -> DexieStickerRepository.create()
  -> one transaction: definition + render asset + instance
  -> StickerObject creates object URL + Three.js Texture

05 · 数据

IndexedDB v2 用三张贴纸表分离内容、资产与位置

数据库名为 dear-desk，版本为 2。v1 的 dailyEntries 原样保留；v2 新增 stickerDefinitions、stickerRenderAssets 和 stickerInstances。创建与删除贴纸都在覆盖三张表的单一事务中完成。

IndexedDB v2 schema
database.version(2).stores({
  dailyEntries: 'date, updatedAt',
  stickerDefinitions: 'id, kind, sourceEntryDate, createdAt',
  stickerInstances: 'id, definitionId, updatedAt',
  stickerRenderAssets: 'id, upstreamCommit'
})

是每天一条记录以及贴纸来源日期的身份； 保存可重建桌面纹理的事实。清除站点数据、切换浏览器或更换设备会失去这些内容，这是当前批准的数据边界，不是同步故障。

06 · 场景

桌面 Canvas 只投影贴纸事实并发出意图

DeskScene 明确注册使用的 Three.js 构造器，按容器尺寸和受限 DPR 配置 R3F root，并用 ResizeObserver 保持绘图缓冲区与视口同步。StrictMode 下的短延迟释放机制避免同一 Canvas 被重复创建 root。

NotebookObject 用透明几何体作为可射线检测的命中区域。DeskContents 让桌垫接收放置 raycast，让 StickerObject 独占选中和拖动事件；两者只调用 store action，不直接访问 Dexie。贴纸拖动过程更新内存位置，pointer up 才提交最终坐标。

StickerObject 为 Blob 创建对象 URL，通过 TextureLoader 加载透明 PNG，并在卸载时同时 dispose() Texture 和 revokeObjectURL()。选中态由四条窄边线组成，不在透明像素后铺设矩形底色。

阶段推进与低帧率保护

NotebookPhase 依次经过 desk → approaching → opening → editing，关闭时反向经过 closing → retreating → desk。R3F 帧循环按墙钟时间插值；DeskScene 另有同阶段计时保护，RAF 被节流时也能收敛。窄视口使用更短计划时长，reduced-motion 直接进入稳定阶段。

07 · 失败路径

失败不会被伪装成成功

失败点当前行为保留的内容
初次读取 IndexedDB 失败store 进入 loadStatus: error，首页显示本地记录不可用无已加载记录
空文本或超过 500 字界面禁用保存，领域层仍会拒绝非法调用textarea 草稿
IndexedDB 写入失败store 进入 saveStatus: error 并显示可见错误组件局部草稿
Sticker Forge 启动或更新失败制作器显示可见错误；取消后返回本子编辑态未保存日记草稿，不写贴纸表
快照空白、无法读取或未放平停留制作阶段并允许重试，不进入放置模式文字、颜色和材质仍在组件内存
贴纸三表事务失败store 显示贴纸错误，不把半成品加入桌面数据库不会只留下部分新记录
移动提交失败显示错误并重新调用 loadStickers() 恢复持久化位置最后一次成功提交的位置
WebGL 初始化失败显示 DOM 降级入口，用户仍可打开本子完整日记读写链路
页面在转场中隐藏打开方向收敛到 editing，关闭方向收敛到 desk不会恢复到半开阶段
端口 5164 被占用Vite 因 strictPort 明确退出本地 IndexedDB 数据不受影响
