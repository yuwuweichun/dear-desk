Dear Desk · 当前事实架构

一条本地记录，分别投影到 DOM 与 3D 桌面

当前应用是一个纯前端、本地优先的单页应用。IndexedDB 保存当天文字记录，Zustand 协调内存状态与本子转场阶段，DOM 承担编辑，唯一的 Three.js 画布负责空间呈现、镜头聚焦和封面开合。

当前实现边界

编号 002 已实现当天记录保存与重开恢复；编号 003 已实现“走近本子、转正、开盖、在纸页 DOM 编辑、反向返回”。贴纸、图片、台灯、过去日期和云同步均尚未接入。

01 · 心智模型

先分清事实、协调与投影

系统没有服务端。用户保存后，浏览器当前 origin 下的 IndexedDB 成为持久化事实；页面内的 Zustand store 是一次运行期间的协调层；DOM 和 Three.js 都是状态的消费者。

01用户意图点击本子、输入、保存
02应用动作Zustand 协调异步状态
03领域与仓储校验文本并读写记录
04IndexedDB保存当前浏览器事实
05双重投影DOM 编辑器与 3D 场景

描述数据边界； 描述 Three.js 的责任。两者共同保证撤掉 3D 场景时，日记数据仍然可以独立读取。

02 · 运行时

React 装载一个应用和一个 WebGL 根

src/main.tsx 创建 repository 与 Zustand store，再通过 Context 注入 React 树。App 同时装载场景外壳和 DOM UI；场景内部使用 React Three Fiber 的 createRoot(canvas) 管理唯一 Canvas。

当前运行时层级
main.tsx
└── AppStoreProvider
    └── App
        ├── DeskScene
        │   └── one HTMLCanvasElement / one R3F root
        │       ├── camera + lights + desk
        │       └── NotebookObject
        ├── header + local status + DOM notebook entry
        └── JournalPanel (only while notebookPhase === 'editing')
为什么没有使用第二个 Canvas

表单、错误信息、按钮和焦点管理由 DOM 更可靠地完成。WebGL 只用于空间关系、光照和遮挡，符合项目的单画布约束。

03 · 主链路

从点击本子到页面重新打开

  1. 启动加载App 挂载后调用 loadToday()，store 以浏览器本地日期向 repository 查询。
  2. 请求打开3D 命中区域或 DOM 等价按钮调用同一个 requestNotebookOpen()，把阶段从 desk 推进到 approaching；重复和越序请求无效。
  3. 完成转场CameraRig 插值 position、Quaternion 与 FOV，随后 NotebookObject 绕书脊展开上封面；只有进入 editing 后 JournalPanel 才挂载并聚焦 textarea。
  4. 保留草稿未保存文字只存在于 JournalEditor 局部 state，不会在每次按键时写数据库。
  5. 显式保存saveEntry(text) 调用 repository；领域函数先去除首尾空白并校验 1 到 500 个字符。
  6. 事务提交Dexie 在一个读写事务中读取旧记录并执行 put，更新时保留 createdAt。
  7. 恢复投影事务成功后 store 更新记录与保存状态；页面重开时从同一 IndexedDB 记录恢复 DOM 内容和“今天有一页”状态。
调用方向
Canvas hitbox / DOM button
  -> appStore.requestNotebookOpen()
  -> approaching -> opening -> editing
  -> CameraRig + NotebookObject visual projection
  -> JournalPanel local draft
  -> appStore.saveEntry(text)
  -> DexieDailyEntryRepository.save(date, text)
  -> normalizeEntryText(text)
  -> db.transaction('rw', dailyEntries)
  -> IndexedDB commit
  -> appStore.entry + saveStatus
  -> DOM status and next-load projection

每类状态只有一个负责人

状态负责人生命周期不允许进入

store 依赖 DailyEntryRepository 接口，不依赖 Dexie 具体类型。测试可以注入内存替身；生产入口才注入 DexieDailyEntryRepository。

05 · 数据

IndexedDB v1 只有一张表

数据库名为 dear-desk，版本为 1。dailyEntries 使用本地日期 date 作为主键，并为 updatedAt 建立索引。当前没有贴纸、图片、台灯或桌面状态表。

DailyEntry
interface DailyEntry {
  date: LocalDate
  text: string
  createdAt: string
  updatedAt: string
}

database.version(1).stores({
  dailyEntries: 'date, updatedAt'
})

是每天一条记录的身份。清除站点数据、切换浏览器或更换设备会失去访问这份记录的能力，这是当前批准的数据边界，不是同步故障。

06 · 场景

Canvas 只呈现空间并发出意图

DeskScene 明确注册使用的 Three.js 构造器，按容器尺寸和受限 DPR 配置 R3F root，并用 ResizeObserver 保持绘图缓冲区与视口同步。StrictMode 下的短延迟释放机制避免同一 Canvas 被重复创建 root。

NotebookObject 用透明几何体作为可射线检测的命中区域。命中后只调用 requestNotebookOpen()，不会直接访问 Dexie；封面铰链、相机姿态、悬停高度与旋转都只存在于帧循环。

阶段推进与低帧率保护

NotebookPhase 依次经过 desk → approaching → opening → editing，关闭时反向经过 closing → retreating → desk。R3F 帧循环按墙钟时间插值；DeskScene 另有同阶段计时保护，RAF 被节流时也能收敛。窄视口使用更短计划时长，reduced-motion 直接进入稳定阶段。

07 · 失败路径

失败不会被伪装成成功

失败点当前行为保留的内容
初次读取 IndexedDB 失败store 进入 loadStatus: error，首页显示本地记录不可用无已加载记录
空文本或超过 500 字界面禁用保存，领域层仍会拒绝非法调用textarea 草稿
IndexedDB 写入失败store 进入 saveStatus: error 并显示可见错误组件局部草稿
WebGL 初始化失败显示 DOM 降级入口，用户仍可打开本子完整日记读写链路
页面在转场中隐藏打开方向收敛到 editing，关闭方向收敛到 desk不会恢复到半开阶段
端口 5164 被占用Vite 因 strictPort 明确退出本地 IndexedDB 数据不受影响
