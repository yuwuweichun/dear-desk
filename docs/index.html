02 · 工作方式

每项任务都经过同一条审核链路

新的独立任务先创建日期编号记录。Codex 可以读取源码、测试和配置来建立事实，但在用户批准前只修改方案文档。

01待确认读取事实并形成方案
02已批准锁定最终执行清单
03实施中按批准范围修改
04待验收展示结果和证据
05已完成由用户接受结果

这里的 意味着每次实现都应形成可运行、可验证的用户结果。实施中若出现会改变范围、主要交互、公共接口或数据结构的新问题，对应改动必须暂停并重新确认。

04 · 一致性

怎样防止文档与源码各说各话

每份任务记录都要保存分析时的源码基线，并在实施结束后补充真实文件、测试结果和方案偏差。涉及产品行为、架构边界或长期约束时，还要同步更新对应的当前事实文档。

  1. 先核对事实从真实源码、测试和运行行为建立现状，区分事实、预计改动、推断和待确认项。
  2. 再锁定范围用户批准后的执行清单是本次改动边界，实施中不能静默扩展。
  3. 最后回写结果把 Git 实际差异、验证证据和当前文档逐项同步，才能进入待验收。

让一份记录可以定位到具体版本； 则负责告诉阅读者项目现在是什么样子。

05 · 产品

“痕迹工作台”的首版边界已经锁定

首版规格已于 2026-08-06 获批。它把核心循环控制在三分钟以内，并围绕桌面、本子、基础贴纸、旧痕迹入口和台灯定义验收场景。

文字与图片贴纸固定使用 Sticker Forge 制作视觉；图片可保留矩形或在本地自动/手动抠图。
双目标确认后的贴纸可以放到桌面或今天的日记，位置和方向本地持久化。
语音记录不进入首版。
本子翻页采用打开的双页模型与受控仿真纸张翻页；左页上一页、右页下一页，不引入真实物理引擎。
台灯职责只做可选氛围状态。
数据位置使用 IndexedDB 本地持久化，不做账号与云同步。

06 · 项目事实

当前应用已经形成双页日记与双 surface 贴纸链路

React 应用通过 Zustand 协调今天、历史页面游标、本子状态机和贴纸工作流；两个 Dexie repository 把正文、图片 source、Forge PNG 与 placement 保存到 IndexedDB v3。WebGL 任意时刻只有一个活跃 Canvas：桌面阶段由 R3F 拥有，制作阶段切换给固定 commit 的 Sticker Forge。

日记链路是“正文日期 + 日记贴纸日期 + 今天 -> 排序页序 -> 只加载可见跨页 -> 左/右整页意图 -> 目标预读 -> CSS 3D 翻页 -> 动画结束提交游标”。历史浏览与始终指向今天的 selectedDate 分离；台灯和旧痕迹抽屉仍未实现。

src/main.tsx组合 repository、store 与 React 根
src/state/app-store.ts本子状态机、页面游标、翻页锁与贴纸工作流
src/features/journal/双页 DOM、今天编辑、历史只读贴纸与 CSS 翻页
src/persistence/IndexedDB v3、日期查询与贴纸四表事务
src/integrations/sticker-forge.ts固定官方 bundle、flat 快照与销毁生命周期
src/features/stickers/制作宿主、材质控件与桌面命令
src/scene/R3F Canvas、本子转场、贴纸放置与 PNG 投影
