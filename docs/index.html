02 · 工作方式

每项任务都经过同一条审核链路

新的独立任务先创建日期编号记录。Codex 可以读取源码、测试和配置来建立事实，但在用户批准前只修改方案文档。

01待确认读取事实并形成方案
02已批准锁定最终执行清单
03实施中按批准范围修改
04待验收展示结果和证据
05已完成由用户接受结果

这里的 意味着每次实现都应形成可运行、可验证的用户结果。实施中若出现会改变范围、主要交互、公共接口或数据结构的新问题，对应改动必须暂停并重新确认。

04 · 一致性

怎样防止文档与源码各说各话

每份任务记录都要保存分析时的源码基线，并在实施结束后补充真实文件、测试结果和方案偏差。涉及产品行为、架构边界或长期约束时，还要同步更新对应的当前事实文档。

  1. 先核对事实从真实源码、测试和运行行为建立现状，区分事实、预计改动、推断和待确认项。
  2. 再锁定范围用户批准后的执行清单是本次改动边界，实施中不能静默扩展。
  3. 最后回写结果把 Git 实际差异、验证证据和当前文档逐项同步，才能进入待验收。

让一份记录可以定位到具体版本； 则负责告诉阅读者项目现在是什么样子。

06 · 项目事实

当前应用已经形成程序化桌面、双页日记与双 surface 贴纸链路

React 应用通过 Zustand 协调今天、历史页面游标、本子状态机和贴纸工作流；四个 Dexie repository 分别把正文、贴纸资源与 placement、铭牌设置、命名场景颜色与预览 Blob 保存到 IndexedDB v5。WebGL 任意时刻只有一个活跃 Canvas：桌面阶段由 R3F 拥有，制作阶段切换给固定 commit 的 Sticker Forge；颜色预览只把当前帧复制到离屏 2D canvas。

日记链路是“正文日期 + 日记贴纸日期 + 今天 -> 排序页序 -> 右页游标 -> 独立按钮意图 -> 目标预读 -> 当前/目标四页只读快照 -> page-flip 折页 -> 完成后提交游标”。书写链路是“阅读 -> 编辑 -> 书写 -> saveJournalEntry(rightDate, draft) -> 收笔”；历史正文可编辑，但历史浏览仍与始终指向今天的 selectedDate 分离。

桌面渲染由三个 plain Three.js Group 工厂和共享 1024px 程序 PBR 材质库组成。V2.2 材质库为 wood、cloth、paper 三个 family 生成 12 张纹理；V12 桌垫与本子封面直接共享 cloth 的中性 albedo、AO、height 和 roughness，再以独立主色和 PBR 参数区分视觉响应。可序列化 spec 是源码事实，userData.sculptRuntime 只在 Canvas 生命周期内暴露节点、socket 和 collider；Mesh、Material 与 Texture 不进入 Zustand 或 IndexedDB。桌垫可见模型和 placement 命中面分离，应用任意时刻仍只有一个活跃 WebGL Canvas。

通用 DOM 控件统一从 src/ui/ 导入，由适配层隔离 animal-island-ui@1.5.1 并补齐原生 disabled/ARIA 语义。第二轮不再恢复旧视觉：日期状态、桌面入口、日记外置命令和贴纸工具保留组件库的浅色胶囊与按压反馈；贴纸工作台整体改为浅薄荷点阵制作空间、暖白预览框和圆角控制面板。常驻品牌/“本地”顶栏已删除，桌面与工作台从视口顶端开始。日记纸页、textarea、文件上传语义、色板、滑杆、Forge mount、贴纸命中和抠图 Canvas 仍属于领域界面。该依赖按用户确认的非商业用途使用，署名与许可证边界记录在 THIRD_PARTY_NOTICES.md。
