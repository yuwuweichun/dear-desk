## 1. 给阅读者的结论

墙纸最终效果由三部分共同决定：墙体几何的面与顶点方向、墙纸图片资源的图案/首尾连续性、以及每个墙面 UV 把几何端点映射到图片横向位置的方式。当前资源已被四墙共享，房间尺寸也保持为 `42 × 33 × 18`；因此本截图更像是共享 UV 映射中某一面端点方向错误。

当前 front 机位的桌后墙是 north。现有 north UV 公式的两个角点在数学上是连续的：north-east 为 `108/150`，与 east 的 north 端点一致；north-west 为 `1`，与 west 的 `0` 在 `RepeatWrapping` 下等价。因此目前不能把“north 墙 UV 方向写反”作为已证实根因。更高价值的检查对象是 helper 最终把 UV 写到哪个 position 顶点，以及图片在 `U≈0.72` 内部接缝和 `U≈1/0` 循环接缝附近的图案内容与梯度。

## 3. 当前源码事实

- 房间模型入口为 `DeskContents -> StudyRoomShell -> createStudyRoomShellModel`。
- `src/scene/models/model-specs.ts` 定义室内宽 `42`、深 `33`、墙高 `18`；本轮未发现需要改变建模尺寸的证据。
- `src/domain/wallpaper-theme.ts` 的 Candy Cloud 使用单张 `/assets/wallpapers/candy-cloud-panorama.png`。
- `src/scene/models/create-study-room-shell-model.ts` 将同一个 panorama texture 赋给西、北、东、南四个墙面材质，并设置 `wrapS: THREE.RepeatWrapping`、`repeat=[1,1]`。
- 当前周长分段为西 `0..33/150`、南 `33/150..75/150`、东 `75/150..108/150`、北 `108/150..1`。
- 西墙空间端点沿北 -> 南，东墙沿南 -> 北，北墙沿西 -> 东的 U 绑定与周长方向一致；北墙窗洞拆分后的面板继续共享北墙对应区间，没有重新从 0 开始。
- 南墙调用为 `horizontalQuad(SOUTH_Z, WEST_X, EAST_X, ..., -1, [SOUTH_U0, 0, SOUTH_U1, 1])`。`horizontalQuad` 在 `inward === -1` 时生成顶点顺序东 -> 西，因此该数组实际把东角绑定到 `SOUTH_U0`、西角绑定到 `SOUTH_U1`，与周长连续方向相反。
- `src/scene/models/model-factories.test.ts` 当前断言检查了南墙 UV 数值区间，但没有检查“南墙西角必须等于 `SOUTH_U0`、东角必须等于 `SOUTH_U1`”这一几何端点语义，因此现有测试可以在区间数值看似正确时漏过方向错误。
- 临时诊断测试直接读取实际生成顶点后确认：南墙空间西角 `(-21, 16.5)` 取 `U=0.5`、空间东角 `(21, 16.5)` 取 `U=0.22`，两者与连续周长期望相反；west/east/north 的外角端点对应正确，north-west 的 `1/0` 由 RepeatWrapping 闭合。
- north 四块面板的实际 position↔UV 绑定连续：西端 `U=1`、东端 `U=0.72`，窗洞左右分片沿同一全墙公式变化，V 也按全墙高度映射。
- 截图中桌后中心墙与左右相邻墙的云层/装饰在墙角出现不自然跳接；这说明最终渲染结果仍不符合视觉连续性，但仅凭截图不能区分“最终顶点 UV 对应错误”和“资源在对应边界内容不连续”。

### 合理推断

架构文档和 `front` 相机代码均确认中心墙是 north；因此已发现的 south UV bug 不能单独解释这张截图。当前 north 接缝仍需结合实际运行画面继续检查资源边界、纹理过滤或相机/墙面命名是否与截图来源一致。
