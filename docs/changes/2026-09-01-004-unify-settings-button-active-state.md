## 1. 给阅读者的结论

右上角颜色按钮在面板展开时会保持高亮，字体按钮虽然正确保持 `aria-expanded=true`，但缺少对应的展开态样式，因此视觉高亮会消失。

建议让字体按钮复用颜色按钮相同的展开态视觉规则。用户点击字体按钮打开菜单后，按钮将持续保持颜色高亮，直到菜单关闭；不改变面板互斥、字体选择或持久化行为。

## 2. 用户需求

用户原始要求：颜色按钮点击展开面板后保持颜色高亮；字体按钮点击展开面板后颜色高亮消失；统一为点击后保持颜色高亮。

Codex 解释：所有右上角会展开内容面板的按钮，在对应面板打开期间都使用同一 active 视觉状态。

## 3. 当前源码事实

- `src/app/App.tsx` 以 `openSettingsPanel` 统一管理 `audio | colors | font | null`，字体按钮通过 `open={openSettingsPanel === 'font'}` 接收展开状态。
- `src/features/settings/ContentFontControl.tsx` 的字体入口已经输出 `aria-expanded={open}`，点击、外部点击和 Escape 也会正确更新该状态。
- `src/scene/SceneColorEditor.tsx` 的颜色入口输出 `aria-expanded={expanded}`。
- `src/styles.css` 仅为 `.scene-color-editor-button[aria-expanded="true"]` 定义展开高亮；`.content-font-button` 没有展开态选择器，因此字体按钮打开菜单时仍使用普通按钮样式。
- `src/app/App.test.tsx` 已验证三个面板互斥和 `aria-expanded` 状态，但未验证字体按钮的展开视觉 class/style。
- 当前工作树另有用户修改：`.codex/config.toml`、`package-lock.json`；本任务不触碰。

## 5. 方案说明

在 `src/styles.css` 中把 `.content-font-button[aria-expanded="true"]` 加入颜色按钮现有的 active 规则，使两个按钮共享同一组颜色、边框、位移和阴影样式。状态来源仍由现有 `aria-expanded` 驱动，避免新增状态。
