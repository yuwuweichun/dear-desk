## 1. 给阅读者的结论

本任务把 Dear Desk 的新 Codex 任务默认模型设为 Luna，并增加一个只读 Sol 深度推理代理。Luna 日常负责代码、命令、修改和验证；只有达到复杂度阈值时，才发送 1～3K Token 的聚焦 Task Packet 给 Sol，拿到结构化建议后继续执行。

## 2. 用户需求

- 默认使用 Luna 读取代码库、搜索资料、运行命令、修改代码和测试验证。
- 复杂架构、跨模块决策、疑难 Bug 或深度推理任务升级给 Sol。
- 升级前把目标、关键代码、约束、已尝试方案和问题压缩为 1～3K Token Task Packet。
- Sol 只接收影响判断的信息，输出结构化方案；Luna 继续实施和验证。
- 用户明确要求直接建立，不等待方案审批。

## 3. 当前源码事实

- 实施前仓库没有项目级 `.codex/config.toml` 或 `.codex/agents/` 自定义代理。
- 根 `AGENTS.md` 已定义文档驱动审批、验证和 Git 约束，但没有模型路由规则。
- 官方 Codex 配置支持项目级 `.codex/config.toml` 的 `model`、`model_reasoning_effort` 和 `[agents]` 设置；自定义代理可放在 `.codex/agents/*.toml` 并覆盖模型、推理强度和沙箱模式。
- 当前工作区已有 `package-lock.json`、`.img2threejs/`、场景源码和概念资产等未提交修改，均不属于本任务。

## 4. 目标与非目标

### 4.1 目标

- 为受信任项目的新任务设置 Luna 默认模型。
- 建立只读 Sol 推理代理、升级阈值、Task Packet 契约和结构化返回要求。
- 保持审批、源码修改、验证和交付责任在 Luna 主任务。

### 4.2 非目标

- 不修改 Dear Desk 产品行为、业务源码、依赖或持久化数据。
- 不让 Sol 并发修改文件或接管最终交付。
- 不为所有任务强制调用 Sol，也不自动创建多个重复审查代理。
- 不修改用户级 `~/.codex/config.toml`，因此该模式仅作用于本项目。

## 5. 方案说明

项目配置把主模型和默认子代理设为 Luna；单独的 `sol_reasoner` 自定义代理固定为高推理强度 Sol 和只读沙箱。根协作规则定义何时调用它，以及 Task Packet 的七段结构。Sol 返回实施就绪的结构化方案后，Luna 复核批准边界并继续执行。

## 7. 风险、边界与回退

| 风险 | 发生条件 | 影响 | 缓解与回退 |
| --- | --- | --- | --- |
| 当前任务未切换到 Luna | 配置在任务启动后新增 | 本任务仍沿用启动时模型 | 新建受信任项目任务后生效 |
| 过度升级给 Sol | 触发条件过宽 | 增加时延与 Token 消耗 | 明确一般任务由 Luna 独立完成 |
| Task Packet 缺少关键事实 | 压缩过度 | Sol 方案基于错误假设 | 强制区分事实/推断并允许只报告真正阻塞的缺口 |
