## 1. 给阅读者的结论

当前北墙窗洞上下/左右墙板分别使用独立四边形，若按各自局部 UV 直接采样，会让窗洞边缘重新开始取图，造成图案错位。修复后四块北墙板将共享北墙的统一局部坐标，窗洞只保留几何缺口，墙纸图案不会因窗口发生平移或重置。

## 2. 用户需求

- 墙纸图片中不应显示 cube-net 的边缘或无关部分。
- 墙纸应覆盖整面墙；窗户中间缺失部分直接由墙体开口表现。
- 窗户附近不做多余的平移、拼接或独立重新布局。

## 3. 当前源码事实

- `src/scene/models/create-study-room-shell-model.ts` 使用 `createQuad()` 为每个墙板写入 `[0,0,1,0,1,1,0,1]` UV。
- 北墙由 `northWindowParts` 拆成四块，每块都从完整 UV 范围重新采样 Candy Cloud 的 north atlas 区域。
- Candy Cloud 主题使用 `src/domain/wallpaper-theme.ts` 中的 3×2 atlas，并由每个墙面材质的 `repeat/offset` 选择图集区域。

## 4. 目标与非目标

### 4.1 目标

- 让北墙四个窗洞周边墙板共享同一套北墙坐标。
- 保持四面墙与顶面的现有五面 atlas 映射。
- 不让窗洞影响图案的横向/纵向连续性。

### 4.2 非目标

- 不重新生成墙纸资产。
- 不改变房间尺寸、窗户尺寸、窗框、墙贴或相机。
- 不实现逐墙编辑、贴图上传或新的墙纸主题。

## 5. 方案说明

将 `createQuad()` 增加可选 UV 范围参数。普通墙面继续使用完整 `[0,1]` UV；北墙四个面板按其在整面北墙中的 x/y 比例写入局部 UV，使四块面板在材质采样上组成一整面墙。窗洞区域没有墙体几何，因此自然不会显示纹理。

## 6. 预计改动与影响评估

- 修改 `src/scene/models/create-study-room-shell-model.ts`：增加矩形 UV 生成能力，为北墙面板传入统一墙面坐标。
- 修改 `src/scene/models/model-factories.test.ts`：验证北墙四个面板的 UV 坐标不再全部从 0 开始。
- 更新 `docs/architecture/study-room-shell.md` 与本记录：说明窗洞使用统一墙面 UV。

### 6.1 核心数据结构变化

### 6.2 上下游与跨模块影响
