## 1. 给阅读者的结论

**当前结论：本方案已弃用。** Minecraft 工作台、火把灯、像素书和体素固定道具均不会按本文实施。以下内容只保留当时的需求解释、资源调研和风险分析，不能视为当前产品方向或待执行清单。

编号 006 不再只是替换一张桌布纹理，而是把唯一 Three.js 画布内的固定桌面场景统一为 Minecraft 式低分辨率像素/体素语言：桌面成为工作台方块语义，灯具采用火把形象，本子改成像素书，其余固定道具、背景、光照和阴影也一起调整，避免只有一个物件像 Minecraft、周围仍是圆润写实低模的拼贴感。

公开资源确实存在。已核验到 Quaternius 的火把与打开的书可下载为 FBX/GLTF 且标注 CC0，Kenney 的书本组可下载为 OBJ/GLTF 且标注 CC0，Sketchfab 也有 CC BY 4.0 的 Blockbench 像素书。但这些候选多数是通用低多边形或体素模型，不会天然形成统一的 Minecraft 场景；明确复刻 Minecraft 原资产的第三方上传还存在原权利风险。建议用本项目自己的 `BoxGeometry`/简单几何和原创小尺寸像素纹理构成最终固定物件，只把许可明确的 CC0 模型作为造型参考或经过实测后选择性使用，不提交 Mojang 原始纹理、模型或来源不明的再上传文件。

该方案只改变固定 3D 场景基线，不新增主题商城、自由装修或第二个 WebGL 画布。现有本子打开、镜头转场、DOM 编辑和贴纸数据链路必须保留；灯具本次只获得火把造型和静态发光表现，不顺带实现尚未审批的开关与持久化状态。

## 2. 用户需求

### 用户原始要求

1. 把桌布改为《我的世界》工作台表面的九宫格，可寻找资源图片作为桌子一个面的纹理。
2. 把灯改成《我的世界》火把的形象。
3. 与九宫格任务放在一起，让整个场景都 Minecraft 化；本子也使用《我的世界》里的书等像素风物件。
4. 指定场景风格为 Minecraft 像素风，并搜索是否有公开模型资源。

### Codex 对需求的解释

- “整个场景”指唯一 Three.js Canvas 内的固定世界与道具，不把 DOM 日记编辑器、表单、错误提示和文档站改成游戏 HUD。
- 风格目标是可辨认的 Minecraft 式方块比例、低分辨率像素纹理、硬边和有限调色板；不使用 Minecraft 标志，也不声称项目与 Mojang/Microsoft 有关联。
- 当前源码没有可见台灯模型，只有环境光和两盏方向光。因此“火把灯”预计是新增一个可见的体素火把物件，并让它附近的暖色光与自发光材质共同承担局部照明；本次不实现台灯开关状态。
- 当前本子承担点击命中、镜头对焦、开合动画和 DOM 编辑对齐。它可以改成像素书的视觉形态，但不能直接替换成不具备这些结构和锚点的静态下载模型。
- “等等”按固定物件一致性处理：桌体/桌垫、本子、铅笔、杯子、左侧纸张物件、背景、雾与灯光都纳入视觉核对；用户生成内容和 DOM 控件只做对比度兼容，不改变其业务语义。
- 外部资源只作为候选。实施时必须逐个确认作者、原始页面、许可、文件格式和再分发条件，并在仓库保存来源说明。

## 3. 当前源码事实

- `src/scene/DeskScene.tsx` 的 `DeskContents` 负责背景、雾、环境光、两盏方向光、桌体、桌垫、左侧纸张物件、本子、贴纸、铅笔和杯子的场景组合。
- 当前没有 `Lamp`、`Torch`、`PointLight` 或灯具开关状态。主光是位置 `[-4, 9, 5]` 的暖色 `directionalLight`，辅光是位置 `[7, 4, -5]` 的冷色 `directionalLight`；场景因此已有“光”，但没有一个与灯光来源对应的可见物件。
- 下方桌体是尺寸 `[12, 0.8, 8]` 的棕色盒体；上方桌垫是尺寸 `[8.7, 0.12, 6.25]` 的绿色盒体。桌垫六个面共用颜色 `#315b57` 的 `meshStandardMaterial`，未加载纹理或拆分顶面材质。
- `Pencil` 使用六边柱、圆锥和圆柱组合；`Mug` 使用 28 段圆柱与 torus 把手；它们的圆润细分度与方块像素目标不一致。
- 左侧纸张物件由两个扁平盒体构成，当前没有独立组件或交互。
- `src/scene/NotebookObject.tsx` 用多个盒体构成本子、页面、封面和装饰线，且已有透明点击命中区、悬停抬起、书脊铰链开合和阶段回调。它适合在原组件内重做像素书视觉，不适合整件替换为无交互语义的第三方静态模型。
- 本子打开后，`src/features/journal/JournalPanel.tsx` 的 DOM 编辑器与纸页对齐。ADR `DD-ADR-20260806-002` 要求表单继续使用 DOM，Three.js 只做状态投影；视觉改造不能把输入框烘焙进纹理。
- 当前唯一 React Three Fiber Canvas 由 `DeskScene` 管理。Texture、Material、Light 和导入模型只应存在于 Canvas 生命周期，不进入 Zustand 或 IndexedDB。
- 工作区已经出现编号 004 贴纸相关的未提交源码改动，`DeskScene` 也包含贴纸放置/选择分支。编号 006 实施时必须在当时真实基线上重新核对并保留这些并行改动，不能用旧文件覆盖。
- 当前仓库没有 `public/` 或 `src/assets/` 图片/模型目录，也没有 GLTF 加载链路。现有依赖包含 Three.js 与 React Three Fiber，但未发现已批准的通用模型资产管线。
- `docs/product/mvp.md` 把主题商城、自由装修列为非目标。合理推断：把默认固定场景统一换成一种视觉基线不等同于给用户开放装修；若新增主题切换或多个场景包，需要另立任务。

## 4. 目标与非目标

### 4.1 目标

- 唯一 3D 场景在第一眼呈现统一的 Minecraft 式像素/体素风，而不是只有桌垫套用一张游戏贴图。
- 桌面形成可辨认的工作台语义：顶面保留清楚的 `3 × 3` 九宫格，桌体侧面与边缘使用一致的像素木纹或原创方块图案。
- 新增可见的火把形灯具，使用方块化木柄、像素火焰/发光块和局部暖光；默认镜头与本子聚焦镜头下都不应遮挡内容。
- 将现有本子重塑为可辨认的像素书，同时保留原点击区域、悬停反馈、书脊开合、阶段状态机和 DOM 编辑衔接。
- 将铅笔、杯子、纸张等固定道具改为同一体素比例和有限调色板；允许用符合功能语义的像素替代物，例如方块羽毛笔或方杯，但不能影响现有可用入口。
- 像素纹理使用最近邻采样、正确颜色空间和受控分辨率；模型/纹理本地构建，不依赖运行时外网。
- 所有外部资源在仓库内记录来源、作者、原始 URL、许可和必要署名；优先 CC0。
- 保留现有贴纸放置坐标、桌面 raycast、镜头、阴影、页面重开和日记流程。

### 4.2 非目标

- 不实现主题选择器、皮肤商城、用户上传场景包、多套主题切换或自由家具装修。
- 不把 DOM 日记编辑器、普通表单和错误提示改成 Canvas 文字或 Minecraft GUI；这会违反已接受的 DOM/场景边界。
- 不使用 Minecraft 标志、启动画面、角色、怪物或大规模世界素材，也不宣称项目得到 Mojang/Microsoft 认可。
- 不直接复制或提交 Minecraft 客户端中的原始纹理、JSON 模型、音效或其他游戏文件。
- 不因页面标注“免费”就采用来源不明、无明确许可或明显未经授权再上传的资源。
- 不新增第二个 WebGL 画布、完整体素引擎、自由方块编辑、动态昼夜、粒子物理或真实火焰模拟。
- 不在本任务实现台灯开关、亮度调节或 IndexedDB 灯光持久化；这些仍属于后续功能切片。
- 不改变贴纸、日记或本子状态的数据结构；不在本次顺带重做用户生成贴纸内容。

## 5. 方案说明

### 5.1 视觉语言与场景范围

先建立一套小而明确的场景规则，再逐物件实现：几何以正交盒体、低段数柱体和薄片为主；纹理采用小尺寸像素画、最近邻采样和整数化 UV 分区；材质保持高粗糙度、低金属度；颜色限制在木色、纸色、炭黑、火焰黄橙和少量功能强调色。摄像机仍使用现有透视投影与转场，不引入完整正交/等距视角，以免破坏已验收的本子聚焦体验。

建议把场景固定物件拆成职责明确的组件，例如 `CraftingDesk`、`TorchLamp`、`PixelWritingTool` 和 `PixelMug`。共享的像素纹理配置集中在一个场景资源模块：统一设置 sRGB、`NearestFilter`、关闭不必要的 mipmap 或按实际缩放保留合适 mipmap，并在卸载时释放 Texture/Material。

### 5.2 工作台与九宫格

原先的绿色桌垫不再作为独立“桌布”语义，而成为工作台顶面的交互平面。顶面显示规整的 `3 × 3` 九宫格，侧面使用原创像素木纹。由于当前桌垫是长方形，建议保留原几何尺寸与 raycast 坐标，在长方形中央放置不拉伸的方形九宫格，剩余区域由同风格边框补足。

材质应直接绑定盒体对应面，不叠加共面平面，避免 z-fighting。贴纸系统继续命中同一世界坐标和同一顶面，视觉分区不自动成为九格吸附逻辑。

### 5.3 火把灯

新增 `TorchLamp` 固定场景组件。造型由少量盒体/交叉像素平面构成，使用原创木柄与火焰纹理；火焰中心可用低强度 emissive 材质，并配一盏范围受控的暖色 `pointLight`。现有方向光仍承担全场景可读性和阴影稳定性，火把光只增加局部来源感，避免单一 PointLight 导致移动端噪点、过曝或阴影预算上升。

火把预计放在桌面后侧或独立小底座上，必须避开本子打开路径、DOM 编辑器投影区域和移动端裁切。它当前始终点亮，不读取或写入应用状态；未来实现 MVP 台灯状态时可在独立任务中把序列化布尔值投影到 emissive/pointLight 强度。

### 5.4 像素书与现有交互

保留 `NotebookObject` 的 group、透明命中区、封面 pivot、阶段回调和世界锚点，只重做可见几何与材质。封面可以参考 Minecraft 书的棕色皮革、浅色纸页和像素边缘，但使用原创纹理与当前产品所需比例；打开后仍保留足够大的浅色纸页承载 DOM 编辑器。

第三方“打开的书”模型可以作为比例参考，但不直接替换组件。若最终确需复用 CC0 模型，也必须拆解或重新设定 pivot、命中盒与页面锚点，并验证封面开合；否则资源复用带来的成本高于用当前盒体结构重绘。

### 5.5 其他固定道具

- 铅笔改成低段数方杆或方块羽毛笔，保持原位置且不承担新交互。
- 杯子改成方形杯/像素药水杯，减少圆柱和 torus 段数；液面继续与杯口关系正确。
- 左侧纸张物件改成像素纸堆、书堆或方块收纳物，但不新增入口。
- 背景、雾和全局光色从当前深绿冷暖混合调整为能衬托木色与火光的中性暗背景，仍保证书页和贴纸对比度。
- 用户生成贴纸与 DOM 面板保留当前信息表达；只在必要时调整选择描边或阴影，使其在新木纹上仍清楚。

### 5.7 失败与回退表现

静态纹理/模型路径应由 Vite 在构建期解析。单个纹理解码失败时，对应物件回退到同调色板纯色材质；可选模型加载失败时使用程序化盒体占位，不能让整个 Canvas suspense 到空白。火把局部光失效时，全局方向光仍保证本子和桌面可读。

### 6.1 核心数据结构变化

领域数据、Zustand 应用状态、repository 接口与 IndexedDB schema 均不变化。预计新增的对象只属于渲染生命周期：

```text
local pixel assets / optional CC0 GLTF
  -> Vite asset URL
  -> THREE.Texture / GLTF scene (Canvas lifecycle)
  -> fixed scene components
  -> existing world positions and interaction anchors

serialized app state
  -> remains unchanged
  -> NotebookPhase still drives NotebookObject
  -> sticker positions still project onto the same desk plane
```

火把本次没有 `isLampOn` 字段，页面重开时总是由静态场景重新创建为点亮状态，因此不需要数据库迁移。若后续增加可切换灯光，应另建任务升级 `DeskState` 与 IndexedDB，而不是预建未使用字段。

### 6.2 上下游与跨模块影响

- 上游资源由 Vite 构建解析，不依赖 CDN；引入 GLTF 时需要核对现有依赖是否已经提供加载器以及是否值得增加缓存/预载逻辑。
- `DeskContents` 继续是场景组合入口；固定物件不直接读取日记 repository 或 IndexedDB。
- `NotebookObject` 的世界坐标、命中盒、封面 pivot、纸页锚点和阶段回调是 `CameraRig` 与 `JournalPanel` 的下游契约，视觉重做不能静默改变。
- 桌垫顶面同时是贴纸放置 raycast 目标。材质/组件拆分可以改变 JSX 组织，但必须保持顶面尺寸、位置、法线方向和点击事件。
- 火把 `pointLight` 会叠加现有灯光并影响所有 `MeshStandardMaterial`。需要控制距离、decay、强度与阴影设置，默认不让第二套动态阴影扩大 GPU 成本。
- 低分辨率纹理会改变贴纸、书页和 DOM 面板周围的视觉对比度；需要同时检查选中态、文本可读性和聚焦镜头遮挡。
- 固定场景资源会增加构建体积。若导入候选 GLTF，必须检查三角形、材质数、贴图尺寸与重复资源；简单物件优先程序化几何。
- 本任务不改变已接受的单 Canvas、本地数据和 DOM 编辑边界，因此不需要新 ADR。若后续决定引入通用场景包系统或品牌资产政策，则需要独立决策。

## 7. 风险、边界与回退

| 风险 | 发生条件 | 影响 | 缓解与回退 |
| --- | --- | --- | --- |
| 原作资产或衍生模型权利不清 | 直接提交 Minecraft 客户端资产，或采用第三方“Minecraft 模型”再上传 | 仓库无法安全分发，且可能造成官方关联误解 | 不采用原始游戏文件；优先原创/CC0；保存来源清单；对明确复刻资源默认拒绝 |
| 场景只像资源拼盘 | 混用不同作者的 low-poly、voxel、圆润模型与原始材质 | 各物件比例、像素密度和调色板不一致 | 先锁定体素网格、像素密度和调色板；外部模型只作参考或统一重制 |
| 九宫格被拉伸或贴错面 | 正方形资源铺满长桌面，或 BoxGeometry 面索引错误 | 工作台语义失真，贴图污染侧面 | 使用中央正方形九格加像素边框；测试 `+Y` 面映射并做俯视截图 |
| 本子交互回归 | 用静态书模型替换现有 group/pivot/命中区 | 点击、开合、镜头聚焦或 DOM 对齐失效 | 保留现有交互骨架，只重做可见子网格；执行完整打开/关闭回归 |
| 火把遮挡或过曝 | 火把位置进入本子动画路径，PointLight 强度/距离过大 | 移动端裁切、书页不可读、颜色失真 | 先固定安全区；限制光照范围；保留不投阴影的局部光；双视口验收 |
| 像素纹理模糊/闪烁 | 默认线性过滤、非整数缩放、远处 mipmap 不合适 | 像素边缘糊、远景摩尔纹或闪烁 | 统一最近邻策略并针对实际距离决定 mipmap；检查不同 DPR 与镜头阶段 |
| GPU 与包体回归 | 为简单物件导入大 GLTF、多材质或高分辨率贴图 | 首屏变慢、移动端掉帧或加载空白 | 程序化几何优先；给资产设预算；构建检查和移动端交互验收 |
| 并行贴纸改动被覆盖 | 实施时从旧基线整体重写 `DeskScene.tsx` | 编号 004 已有改动丢失或行为回归 | 实施前重新读取 Git 差异；局部编辑并保留贴纸调用链；跑贴纸测试 |
| 资源加载失败拖垮场景 | 纹理/GLTF URL 或解码失败且无回退 | Canvas 空白，本子入口不可用 | 每个资源提供纯色/程序化回退；全局光不依赖火把资源 |

回退分两级：若外部模型不合适，回退到本任务的程序化体素几何；若整体风格实施产生严重回归，移除新增资产与固定组件，恢复当前纯色桌垫、现有本子几何、Pencil/Mug 和全局灯光。两种回退都不删除或迁移用户数据。

## 9. 待确认项与决策

### 决策 1：相似度边界

**建议：采用“Minecraft 式像素/体素语言”，不复制 Mojang 原始纹理和模型。** 用户会看到明确的工作台九宫格、火把灯和像素书，但最终图案由项目原创。这样能满足风格目标，也避免把第三方再上传的 CC 标签误当成原作授权。

另一选项是要求与游戏原资产完全一致；这需要用户提供有权使用和再分发的来源，并接受品牌/衍生资产审查，实施不能仅靠搜索结果推进。

### 决策 2：资源实现方式

**建议：程序化简单几何 + 原创小尺寸 PNG 为主，CC0 模型只在检查后选择性使用。** 火把、书、杯子和书写工具都能由少量盒体可靠表达，容易保留交互锚点并控制包体。全面导入第三方 GLTF 会增加材质统一、pivot 修复和加载回退成本。

### 决策 3：本任务的“灯”范围

**建议：本次实现固定点亮的火把造型与局部暖光，不实现开关和持久化。** 这与用户当前提出的场景形象一致，也不把 MVP 台灯状态功能静默塞进视觉任务。开关、亮度和重开恢复仍需独立任务审批。

### 决策 4：Minecraft 化的 UI 边界

**建议：只改 Three.js 场景，DOM 日记编辑器保持可访问的现有形态。** 可调整编辑器周围颜色以适配新书页，但不使用像素字体替代正文输入，也不把表单渲染到 WebGL。

### 决策 5：其他桌面道具映射

**建议：铅笔改为方块羽毛笔/方杆笔，杯子改为方形像素杯，纸张改为像素纸堆；保留各自位置与功能。** 这能完成“整个场景”一致性，又不会新增物品系统。若用户希望指定为 Minecraft 中某个精确物品，需要在批准前列出对应映射。
