## 1. 给阅读者的结论

项目之前已经分析过这个问题，但只完成了诊断和台灯调研，没有完成本次“光影系统优化”的实施。`DD-20260817-006` 已确认截图中的白边不是单一镜面反射：页口浅色漫反射被多组光源叠加压白，封面布面 `bumpScale = 0.35` 过大造成掠射角闪点，连续书壳共享顶点的平均法线又放宽了边缘高光。

建议先建立稳定的光能与材质基线：降低本子布面 bump、限制页口与纸张的漫反射能量、收紧连续壳体边缘法线，并重新平衡主光、补光、半球光、PMREM 环境和曝光。台灯可以加入，但应作为固定位置的可见氛围物件和局部暖光，不应作为泛白问题的替代修复。用户入口建议先提供有限的“台灯开关 / 光影预设”而不是任意强度滑杆；保存可序列化的枚举或布尔状态，避免把 Three.js 对象暴露为产品设置。

## 3. 当前源码事实

- `docs/changes/2026-08-17-006-diagnose-notebook-edge-glare.md` 已记录异常亮线的三项叠加原因，并建议用 bump、主光和硬边法线三个最小实验确认；该任务只读完成，没有修复。
- `docs/changes/2026-08-13-010-explore-desk-lamp-lighting.md` 已调研台灯方案，推荐固定位置的可见发光灯罩加暖色 `SpotLight`，并要求保持单投影光预算；该任务没有实现台灯。
- `src/scene/DeskScene.tsx` 主场景当前使用强度 `2.05` 的暖色投影 `DirectionalLight`、强度 `0.42` 的冷色补光、强度 `1.15` 的 `HemisphereLight` 和 `SceneEnvironment` 强度 `0.42`；主光、补光、环境光与 ACES exposure 共同决定最终能量。
- `src/scene/models/SceneEnvironment.tsx` 使用 `RoomEnvironment` 经 PMREM 提供环境反射；它不是局部灯光，也没有 Bloom、SSR 或其他反射后处理。
- `src/scene/models/material-library.ts` 的本子封面是 `MeshPhysicalMaterial`，当前测试事实为 `roughness = 0.8`、`sheen = 0.18`、`anisotropy = 0.22`、`bumpScale = 0.35`；纸张和页口是浅色高粗糙度材质，但高粗糙度不能阻止漫反射被整体照亮。
- `src/scene/models/create-notebook-model.ts` 的连续书壳几何对共享索引顶点统一 `computeVertexNormals()`；锐角和端盖没有完整硬边分割，因此边缘高光可能比几何圆角更宽。
- `src/scene/ModelReviewScene.tsx` 有 `grazing`、`neutral`、`reference-match` 三种仅供模型评审路由使用的灯光配置；`App.tsx` 从 URL 读取 `light`，当前没有证据表明该入口是主桌面用户设置。
- `docs/product/mvp.md` 已批准“状态明确的台灯”：台灯是可选氛围状态，灯光状态可以保存；首版不包含复杂主题商城或装修系统。现有产品约束还要求持久化模型与 Three.js 对象分离、保持单活跃 WebGL Canvas。

**合理推断：** 当前主场景的泛白优先级高于是否增加新灯具；直接叠加台灯或提高发光强度会放大纸口压白风险。用户可见控制若开放，优先使用两个或三个经过校准的预设，能在不暴露渲染参数的情况下支持氛围选择。

## 4. 目标与非目标

### 4.1 目标

- 修复截图所示本子纸口压白、封面边缘闪点和过宽轮廓高光。
- 建立材质、直接光、环境光、曝光和阴影之间可复现的光能基线。
- 在不突破单投影光和移动端性能边界的前提下评估固定位置台灯。
- 提供清晰、有限、可持久化的光影切换入口，并覆盖重新打开页面后的状态恢复。

### 4.2 非目标

- 不引入昼夜系统、任意家具摆放、主题商城或连续亮度调色台。
- 不引入第二个 WebGL Canvas、实时路径追踪、复杂全局光照或重型后处理作为首切片依赖。
- 不把截图直接复刻为新模型或改动本子比例、开合交互和日记数据结构。

## 5. 方案说明

### 5.1 第一阶段：光能与材质基线修复

1. 将本子封面 bump 调回与桌垫同数量级的低值，并重新核对 `roughness`、`sheen` 与 `anisotropy`，保留可读织纹但压制掠射角闪点。
2. 对纸面/页口使用更保守的漫反射颜色或材质响应，避免浅色表面在主光、半球光和 PMREM 叠加后接近纯白。
3. 为连续书壳锐角和端盖拆分必要顶点或设置明确硬边法线，只让真实圆背保持平滑。
4. 以主方向光为唯一投影光，逐步平衡主光、补光、半球光、环境强度和曝光；记录可回归的数值与截图验收标准。

### 5.2 第二阶段：可见台灯与有限预设

建议在桌面右后方放置固定、低矮、有灯罩的装饰台灯，不占用本子和贴纸工作区。灯罩内使用暖白 emissive 材质；台灯光先采用不投影的有限范围 `SpotLight`，由现有方向光继续承担唯一实时阴影。只有当阴影来源明显违和时，才另行批准“单投影权从方向光切换到台灯”的方案。

用户入口建议为“光影预设”按钮：`自然`（当前校准基线）、`台灯`（暖色局部氛围）和可选的 `柔和`（降低对比，适合阅读）。台灯本体也可以作为同一状态的可点击目标。首版不开放任意强度、色温或曝光滑杆；这些参数需要设计与性能验证后再决定是否公开。

## 6. 预计改动与影响评估

批准后预计形成以下调用链：DOM 按钮或台灯命中 -> Zustand 可序列化光影状态 -> IndexedDB 读写（如状态已有仓储则扩展版本）-> `DeskScene` 投影为光源、台灯模型和材质参数 -> 3D 场景更新并保持单 Canvas。

预计涉及 `src/scene/DeskScene.tsx`、`src/scene/models/material-library.ts`、`src/scene/models/create-notebook-model.ts`、状态/持久化模块、对应 UI 控件和测试；实际文件需在批准后按源码核对，不预先承诺新增依赖。

### 6.1 核心数据结构变化

第一阶段无持久化结构变化。若批准第二阶段，建议仅增加 `lightingPreset: 'natural' | 'lamp' | 'soft'` 或等价的 `lampOn: boolean`，默认值为当前自然基线；不保存 `THREE.Light`、材质实例、纹理或场景对象。IndexedDB 迁移必须向后兼容旧桌面状态。

### 6.2 上下游与跨模块影响

会影响 Three.js 材质库、主场景灯光、桌面台灯模型、Zustand 状态、IndexedDB repository、桌面 UI 和自动/浏览器验证；本子交互、贴纸数据和日记 DOM 不应被光影状态耦合。

## 7. 风险、边界与回退

| 风险 | 发生条件 | 影响 | 缓解与回退 |
| --- | --- | --- | --- |
| 台灯叠加导致再次泛白 | 暖色 SpotLight 与现有主光、PMREM 未重新配平 | 纸口和浅色贴纸失去层次 | 先完成基线修复；台灯默认不投影并限制距离/锥角；保留自然预设回退 |
| 多投影光超出性能预算 | 同时启用方向光和台灯阴影 | 移动端帧率下降、阴影跳变 | 维持单投影光预算；真实灯影切换另行审批 |
| 参数滑杆造成不可控组合 | 用户任意调整曝光、强度、粗糙度 | 视觉不可复现、验收困难 | 首版只开放经过校准的有限预设 |
| 只调灯光未调材质 | 保留过大的 bump 或平均法线 | 边缘闪点仍在 | 材质、几何和光能作为同一验收组逐项测试 |

## 15. 补充诊断：封面下沿窄白线

用户新截图中的白线位于绿色封面下沿与浅色页芯侧面的交界处，形态连续、稳定且没有 Bloom 或屏幕空间反射的源码链路，因此不是新的后处理反射问题。当前最可能是两个因素叠加：

- `createTextBlock()` 创建的圆角页芯文本块使用 `materials.paperEdge`，其上沿直接暴露在主方向光下；即使粗糙度为 `0.98`，浅色纸材质仍会产生局部漫反射亮边。
- `createPageEdgeInstances()` 另外创建 12 层薄页口实例，最上层与文本块上沿距离很近；封面下沿、文本块边缘和薄页口层在同一视线缝隙内同时可见，会形成一条比实际纸面更亮的窄线。

这与第一阶段已经修复的底面宽白带不同：封面 bump、主光能量和端盖法线调整已经降低了大面积泛白，但没有改变页芯上沿的几何可见性和 `paperEdge` 角色复用。建议下一步做一个小范围修复实验：为页芯主体和薄页口层拆分材质角色，并将封面下沿附近的页芯主体轻微下移/内缩；先验证白线是否消失，再决定是否调整颜色。该实验需要新的实施批准，当前未修改源码。
