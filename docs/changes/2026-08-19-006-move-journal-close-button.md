## 1. 给阅读者的结论

当前关闭按钮定位在日记面板右上角以内，按钮本体会压到右页页眉区域。建议只调整按钮的响应式定位，把桌面端按钮向右、向上各移动约 `20px`，让它跨出纸页内容区并落在本子右上边框外侧；移动端使用约 `14px` 的较小外移量，保留触达空间。按钮外观、尺寸、关闭行为和未保存草稿保护均保持不变。

## 2. 用户需求

- **用户原始要求**：关闭按钮太近并遮挡 UI，需要再往右上角一点。
- **Codex 解释**：被指出的是打开日记后右上角圆形“关闭本子”按钮；目标是消除它对右页顶部信息的遮挡，不重新设计按钮或移动右侧阅读/编辑工具列。
- **验收意图**：关闭按钮与右页页眉内容明显分离，同时仍清晰可见、可点击。

## 3. 当前源码事实

- `src/features/journal/JournalPanel.tsx` 的 `JournalBook` 在 `.journal-panel` 内直接渲染 `IconButton`，类名为 `.journal-close-button`，图标使用 Lucide `X`，无额外定位容器。
- `src/styles.css` 桌面规则把按钮设为 `position: absolute; top: 12px; right: 12px; z-index: 30`。按钮因此位于面板边界以内，截图显示它覆盖右页页眉右上区域。
- 同一文件的移动端媒体规则使用 `top: 8px; right: 8px`，并将按钮固定为 `40px × 40px`。
- `src/ui/theme.css` 只负责按钮颜色、边框、阴影和 hover 反馈，不负责定位。
- `closeNotebook()` 在保存中忽略关闭，在草稿 dirty 时提示先收笔，否则调用 `requestNotebookClose()`。本任务不改变这条调用链。
- `src/features/journal/JournalPanel.test.tsx` 已覆盖关闭按钮的 dirty 草稿拦截和成功关闭行为，但没有验证 CSS 几何位置。
- **文档与源码冲突检查**：`docs/product/mvp.md` 与 `docs/architecture/system-overview.html` 描述关闭及 dirty guard 行为，但未规定关闭按钮的像素位置；未发现与本次布局修复冲突的 ADR。

## 4. 目标与非目标

### 4.1 目标

- 桌面端将关闭按钮从页内右上角移到本子右上边框外侧，避免遮挡右页页眉。
- 移动端同步采用较小的右上外移量，保持按钮完整可见和可点击。
- 保持关闭按钮现有视觉、层级、无障碍名称与交互行为。

### 4.2 非目标

- 不调整右页日期、标题、正文或右侧阅读/编辑工具列布局。
- 不修改按钮尺寸、图标、颜色、阴影或 hover 状态。
- 不改变关闭、保存、dirty 草稿保护或本子状态机。
- 不修改任何持久化数据、公共接口或 Three.js 场景。

## 5. 方案说明

直接修改 `.journal-close-button` 的 `top` 与 `right` 偏移最符合现有所有权：按钮已经相对 `.journal-panel` 绝对定位，遮挡来自内缩的正值坐标，无需改变 DOM 或引入新容器。

建议桌面规则由 `top: 12px; right: 12px` 改为 `top: -8px; right: -8px`，相当于向上、向右各移动 `20px`。移动端由 `8px` 改为 `-6px`，相当于各移动 `14px`；移动端 `.journal-panel` 右侧已预留 `68px`，可容纳 `40px` 按钮。负偏移只让按钮跨出纸页内容区，不改变其定位参照或 z-index。
