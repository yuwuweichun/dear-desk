## 1. 给阅读者的结论

墙纸是房间壳体的“表面主题”，不是墙面贴纸或通用装修系统。当前首版只实现用户确认的 Candy Cloud：一张严格按概念图视觉语言制作的 3×2 五面 cube-net 图集，映射四面墙与顶面，内容可在折叠关系中连续，不使用可重复平铺。

用户将看到一个墙纸选择器，切换后实时改变墙面的颜色、重复花纹和表面粗糙感；桌面、地板、窗框和墙面贴纸保持不变。选中的主题可以在刷新后恢复，但不扩展为家具装修、自由贴墙或主题商城。

## 2. 用户需求

### 原始要求

- 添加墙纸个性化系统。
- 提供不同风格的颜色、花纹、质感墙纸。
- 希望参考现实或生活化游戏中的场景，选择好看、容易实现、无需美术资产的程序化方案。

### Codex 解释

- “墙纸”指书房壳体墙面的整体表面主题，不是可移动的墙面贴纸。
- 先解决一组少量高质量预设，再考虑自定义参数；避免把首版做成完整房间编辑器。

## 3. 当前源码事实

- `src/scene/models/create-study-room-shell-model.ts` 创建四面墙、北墙窗洞、窗洞侧壁和墙面材质；墙体当前共享一套墙面材质和程序纹理。
- 当前墙面使用 `512 × 512` 程序纹理，包含 albedo 与同一份数据纹理，数据纹理复用于 roughness、bump 和 AO；材质为 `THREE.MeshStandardMaterial`。
- `src/scene/models/model-specs.ts` 的 `STUDY_ROOM_MODEL_SPEC` 是房间尺寸、窗洞和纹理重复的单一规格来源。
- `src/scene/DeskScene.tsx` 挂载 `StudyRoomShell`，房间表面禁用射线；墙面贴纸由 `WallStickerObject` 独立投影，持久化使用现有贴纸表。
- `src/domain/scene-color-preset.ts`、`src/persistence/scene-color-preset-repository.ts` 和 `src/features/...` 的现有颜色预设模式已经支持命名、应用、删除与 IndexedDB 保存，但当前只保存九项场景颜色，不包含墙面纹理主题。
- `docs/product/mvp.md` 明确首版不包含完整主题商城和自由家具装修；墙面装饰属于贴纸系统，不能与墙体主题混为一体。
- 已确认的测试事实：房间模型有资源释放和预算测试；当前墙面纹理/材质对象是房间工厂私有资源。

### 合理推断

- 最小实现可以把主题参数作为房间模型创建参数传入，在重建 `StudyRoomShell` 时生成对应纹理；不需要新增 WebGL Canvas，也不需要改变墙贴数据结构。
- 由于墙体四个方向共享材质，第一版适合“全房间统一墙纸”；按墙面分别换色会明显扩大状态、编辑器和预览范围。

## 4. 目标与非目标

### 4.1 目标

- 提供 4 款程序化墙纸预设，覆盖素色、条纹、织物/菱格、木格栅四种明显不同的风格语言。
- 主题至少控制：基础色、花纹生成方式、粗糙度/凹凸强度、纹理重复率。
- 主题切换不改变墙体尺寸、窗洞、踢脚线、墙贴位置或现有交互。
- 主题在页面刷新后恢复；默认主题保持当前浅暖橄榄灰墙面视觉。
- 增加一条最小自动测试，验证主题规范化/默认值和工厂资源释放。

### 4.2 非目标

- 不做用户自由调色、渐变编辑器、纹理上传或主题商城。
- 不做每面墙独立主题、墙纸卷边、施工缝、贴墙动画或真实物理。
- 不新增图片、模型、字体、第三方材质库或第二个 WebGL Canvas。
- 不把墙纸主题与墙面贴纸合并，也不修改贴纸 IndexedDB schema。

## 5. 方案说明

### 5.1 建议的首批预设

| 主题 | 现实/游戏灵感 | 程序化做法 | 推荐程度 |
| --- | --- | --- | --- |
| 暖灰泥 `plaster` | 日式工作室、生活模拟游戏的安静墙面 | 低频 value noise + 很弱的细颗粒；低对比 albedo，低强度 bump，高 roughness | 首发默认。最稳，最不抢桌面和窗户 |
| 细竖纹纸 `pinstripe-paper` | 旧书房、文具店、轻复古房间 | 规则竖线 + 微小横向纸纤维噪声；条纹明度差控制在低范围 | 首发。最容易做出“墙纸”识别度 |
| 亚麻菱格 `linen-diamond` | 手帐房、布艺工作室、生活化游戏软装 | 两组交叉方向 ridge 形成菱格；颜色差很小，roughness 变化大于颜色变化 | 首发。复用现有 cloth 思路，和 Dear Desk 气质最合 |
| 胡桃木格栅 `warm-wainscot` | 木质书房、Animal Crossing/生活模拟类房间 | 上半墙细竖木纹，下半墙较暗横向木板；只用规则 grain、缝线和颜色层 | 可选首发。需要让窗框/地板保持层次，视觉收益高 |
| 柔和彩粉 `soft-check` | 儿童房、轻生活游戏 | 低对比大格纹 + 纸张颗粒 | 后续候选。容易显得廉价，需用户验收后再保留 |
| 深墨植物影 `botanical-shadow` | 夜间书房、植物主题房间 | 由少量椭圆叶片/枝条的 signed-distance 形状重复生成，叠加暗纹 | 后续候选。好看但更容易喧宾夺主，不作为第一批默认 |

### 5.2 实现边界

建议新增一个很小的 `WallpaperTheme` 数据结构和一个生成函数，而不是抽象出通用材质框架。生成函数直接返回墙面 albedo/data 两张 `DataTexture`，继续沿用房间工厂现有的 `makeTexture`、重复模式、PBR 通道和 dispose 生命周期。

初始主题只由代码常量定义。用户选择状态可以先保存为 `localStorage` 的主题 id；若后续需要与场景颜色预设绑定，再扩展现有预设结构，不提前迁移 IndexedDB。

建议 UI 放在已有“房间背景”工具附近，使用单选卡片或小型列表；卡片可以用 CSS 生成色块/条纹缩略图，不必为主题额外捕获 3D 图片。

## 6. 预计改动与影响评估

- `src/scene/models/create-study-room-shell-model.ts`：把固定墙面纹理生成替换为主题参数驱动，保留当前材质、纹理数量和释放逻辑。
- `src/scene/models/model-specs.ts` 或相邻新建的最小领域文件：定义主题 id、默认主题和四款参数；是否新建文件待实施时按现有目录模式决定。
- `src/scene/DeskScene.tsx`：接收当前墙纸主题并把它传给 `StudyRoomShell`，主题变化时沿现有房间重建路径刷新。
- `src/app/App.tsx` 与 `src/styles.css`：增加主题选择入口和本地恢复；复用既有工具栈/面板样式。
- `src/scene/models/model-factories.test.ts` 或相邻测试：增加主题资源与默认行为检查。
- `docs/architecture/study-room-shell.md`、`docs/product/mvp.md` 和本记录：回写真实主题所有权、持久化和验收结果。

### 6.1 核心数据结构变化

预计新增 `WallpaperThemeId = 'plaster' | 'pinstripe-paper' | 'linen-diamond' | 'warm-wainscot'`。Three.js 对象仍是视觉投影，不进入持久化；持久化只保存当前主题 id。现有 `StickerInstance`、贴纸仓储和 IndexedDB v5 不变。

### 6.2 上下游与跨模块影响

影响房间模型创建、桌面首页设置入口和刷新恢复；不影响桌面模型、本子、日记、贴纸制作、墙贴坐标、相机、声音和单 Canvas 约束。主题变化会触发房间材质/纹理重建，因此必须继续释放旧模型资源。

## 7. 风险、边界与回退

| 风险 | 发生条件 | 影响 | 缓解与回退 |
| --- | --- | --- | --- |
| 花纹过强 | 条纹/菱格对比过高 | 墙面抢过桌面和本子 | 限制 albedo 对比，优先把差异放在 roughness/bump |
| 重建闪烁或泄漏 | 主题切换未走现有 dispose | GPU 纹理累积或短暂空场景 | 复用现有房间重建路径，补资源释放测试 |
| 与窗框/地板冲突 | 木格栅和暖木材质色相接近 | 房间层次变平 | 木主题只做墙面，中低墙板与窗框使用明确明度差 |
| 移动端性能下降 | 每种主题生成过多纹理或 draw call | 首屏或切换变慢 | 保持两张墙纹理、512²、零新增网格；必要时延迟生成非当前主题 |
| 范围膨胀 | 用户把墙纸理解为逐墙装修 | 状态和 UI 迅速复杂化 | 第一版明确为全房间主题，逐墙编辑另立任务 |

- 自动测试：主题 id/default 规范化、Candy Cloud 五面图集映射、房间资源释放、主题切换不改变房间结构。
- 构建与静态检查：现有 lint、全量测试、production build、文档引用检查。
- 浏览器验收：本任务若批准实现，建议由用户明确要求后再做桌面/移动视觉检查；默认不把浏览器验收写成已执行。
- 持久化与恢复：选择主题、刷新页面，墙面恢复相同主题；清除 localStorage 后回到 `plaster` 默认主题。
- 成功标准：Candy Cloud 严格使用概念图的粉彩云朵、星星和糖果纸屑语言，五面内容不重复平铺且可按 cube-net 连续；窗口、墙贴、自由视角和背景显隐均保持现有行为。

## 9. 待确认项与决策

1. 是否批准先做 4 款全房间统一主题：建议批准；它覆盖用户目标且不触碰完整装修非目标。
2. 首发是否包含木格栅：建议包含，但作为“可选第四款”，若用户更偏柔和风格可替换为 `soft-check`。
3. 主题是否与现有九色场景预设一起保存：建议首版不绑定；先保存独立主题 id，避免改动 IndexedDB v5 结构。
4. 是否需要用户自定义颜色：建议暂不做；等固定预设证明需求后再增加单色调参，不提前做编辑器。
