## 1. 给阅读者的结论

首次打开日记本时，日记 DOM 先按 CSS 默认字体绘制，字体资源加载完成后才应用用户选择的内容字体，形成首屏闪烁。现已把当前内容字体预加载接入项目启动 Loading 阶段；Loading 结束后才允许进入可交互桌面，字体失败时继续使用已有字体回退。

## 2. 用户需求

用户希望第一次打开日记本时直接显示已选字体，不出现默认字体到选中字体的跳变。字体切换、日记内容和数据结构不改变。

## 3. 当前源码事实

- `src/app/App.tsx` 从 `localStorage` 读取全局字体，并把 `contentFont` 传给 `JournalPanel`。
- `src/features/journal/JournalPanel.tsx` 在 `notebookPhase === 'editing'` 时挂载 `JournalBook`；字体 CSS 通过 `data-journal-font` 和 CSS 变量控制。
- `src/domain/journal-font.ts` 定义字体 ID/字体栈，但当前日记挂载前未确认 `document.fonts` 已完成加载。
- `src/styles.css` 的日记内容字体使用 CSS `font-family`，浏览器可能先以回退字体绘制，再在本地字体加载后替换。

## 4. 目标与非目标

### 4.1 目标

- 首次打开日记本时，日记可见内容直接使用已选内容字体或其稳定回退。
- 保持字体选择、持久化和铭牌字体逻辑不变。

### 4.2 非目标

- 不重做字体资源、不修改字体许可、不改变 UI 字体。
- 不改变日记打开动画、数据加载和持久化模型。

## 5. 方案说明

在日记面板挂载前对当前内容字体执行一次浏览器原生 `document.fonts.load()` 预加载，并在预加载期间保持日记内容不可见/不挂载；加载完成后显示日记。若浏览器不支持 Font Loading API 或字体加载失败，按现有 CSS 回退继续打开，避免阻断日记。

## 6. 预计改动与影响评估

实际修改 `src/domain/journal-font.ts` 增加可复用预加载函数，`src/app/App.tsx` 将字体就绪纳入启动 Loading 和运行中切换的就绪条件，`src/app/App.test.tsx` 与 `src/domain/journal-font.test.ts` 补充覆盖。未修改 `JournalPanel.tsx`，因为字体在日记挂载前已由应用层准备。

### 6.1 核心数据结构变化

无持久化或业务数据结构变化；仅增加页面内短生命周期的字体准备状态。

### 6.2 上下游与跨模块影响

影响项目启动遮罩和运行中字体切换时机；铭牌、字体入口、IndexedDB 和 localStorage 不变。

## 7. 风险、边界与回退

| 风险 | 发生条件 | 影响 | 缓解与回退 |
| --- | --- | --- | --- |
| 字体加载较慢 | 首次缓存为空 | 日记内容稍后出现 | 仅等待当前字体；失败或 API 不可用时立即使用 CSS 回退 |
| 字体资源加载失败 | 文件缺失或浏览器拒绝加载 | 选中字体不可用 | 浏览器继续使用既有字体栈，不阻断打开 |
