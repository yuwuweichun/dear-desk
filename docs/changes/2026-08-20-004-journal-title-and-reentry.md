## 1. 给阅读者的结论

当前保存成功后并没有锁死日记：界面会退出 textarea，但仍留在“编辑”模式，按钮回到“书写”，理论上可以再次打开同一页。当前标题不是数据，而是 `JournalPanel`/`JournalPage` 根据日期写死的“今天”或“日记”，因此不能编辑，也无法随正文一起恢复。

建议将标题纳入 `DailyEntry` 的本地持久化字段，并把书写态的标题渲染为可编辑输入。保存正文和标题后回到阅读态；再次点击“书写”时同时恢复正文和标题。没有标题的既有 IndexedDB 记录继续按今天“今天”、历史页“日记”兼容显示。

## 2. 用户需求

### 用户原始要求

1. 保存之后再次点击书写按钮会跳变，无法稳定再次书写，需要修复。
2. 标题“今天”（示例 `<h2>今天</h2>`）需要可编辑。
3. 从阅读模式切换到编辑模式时，默认直接开启书写状态。

### Codex 解释

- 调整为“阅读 → 编辑并直接书写 → 收笔”流程；收笔后不锁定页面，再次进入书写必须稳定复用当前已保存内容，不发生页面跳变或焦点丢失。
- 标题与正文同属一条按日期保存的日记记录，今天默认标题为“今天”，历史记录默认标题为“日记”。
- 标题和正文都必须在页面重开后恢复；标题为空或超长时不允许保存，并保留草稿供修正。

## 3. 当前源码事实

- `src/features/journal/JournalPanel.tsx` 中 `saveDraft` 成功后把 `writingPhase` 设为 `idle`、清空 `draftDate`，所以保存后退出 textarea；同一组件在 `journalMode === 'editing'` 且非书写态时仍渲染“书写”按钮，`startWriting` 会用当前正文初始化草稿。
- `src/features/journal/JournalPanel.tsx` 与 `src/features/journal/JournalPage.tsx` 的 `<h2>` 分别直接渲染 `rightDate === selectedDate ? '今天' : '日记'` 与 `isToday ? '今天' : '日记'`，没有标题输入或状态。
- `src/domain/daily-entry.ts` 的 `DailyEntry` 只有 `date`、`text`、`createdAt`、`updatedAt`；`DailyEntryRepository.save` 只接收日期和正文。
- `src/persistence/daily-entry-repository.ts` 通过 Dexie `dailyEntries` 表保存记录；`src/persistence/database.ts` 当前版本为 v4，旧记录没有标题字段。
- `src/state/app-store.ts` 以 `DailyEntry` 作为当前页与日期页缓存，`saveJournalEntry(date, text)` 保存后更新缓存。
- `src/features/journal/JournalPanel.test.tsx` 已覆盖保存后回到阅读、历史页编辑、失败保稿，但未覆盖保存后再次书写和标题恢复。

## 4. 目标与非目标

### 4.1 目标

- 保存成功后保留编辑模式，并允许再次点击“书写”编辑同一日期的正文和标题。
- 修复再次书写时的跳变：书写表单只在书写状态切换时稳定挂载，保存后再次打开不丢失草稿、焦点或日期。
- 阅读切换到编辑时默认进入书写状态，不再先显示一个需要额外点击“书写”的中间态。
- 今天页默认标题为“今天”，历史页默认标题为“日记”；用户可在书写态编辑标题。
- 标题与正文一起通过 `DailyEntryRepository` 保存到 IndexedDB，并在翻页、阅读和页面重开后恢复。
- 兼容没有标题字段的 v1-v4 既有记录，不要求用户迁移或重新保存。
- 增加领域校验、repository、store、组件和持久化测试。

### 4.2 非目标

- 不改变按日期组织、贴纸关联、字体偏好或双页翻页模型。
- 不实现标题历史版本、富文本、自动保存、云同步或跨设备同步。
- 不允许在阅读态直接修改标题；切换到编辑模式即进入包含标题和正文的书写表单。

## 5. 方案说明

将 `title` 加入 `DailyEntry`，repository 的 `save` 改为接收 `(date, text, title)`，在领域层规范化标题并限制长度。切换到编辑模式时直接以当前记录标题或日期默认值初始化 `titleDraft` 与正文草稿，并将焦点交给正文；收笔时一次性提交标题和正文。保存成功后稳定回到编辑模式的非书写态，再次点击书写只切换同一表单状态，不重新挂载整页。阅读页只读取 `entry.title`，缺失字段使用兼容默认值。这样保存边界仍是单条按日期事务，标题不会成为 React 或 Three.js 的第二份持久化事实。

## 6. 预计改动与影响评估

### 6.1 核心数据结构变化

- `DailyEntry` 新增 `title: string`。
- `DailyEntryRepository.save(date, text, title)` 新增标题参数；实现对旧记录保留 `createdAt`，更新正文和标题的 `updatedAt`。
- IndexedDB `dailyEntries` 的索引不变，新增字段无需改变主键；数据库版本是否递增由实施时根据 Dexie 对象迁移测试确认，预计无需显式 schema 版本升级，但需验证旧记录读取。
- 标题默认值由日期决定：当前日期为“今天”，历史日期为“日记”；旧记录缺失字段时在读取/投影层补齐。

### 6.2 上下游与跨模块影响

- 修改 `src/domain/daily-entry.ts`、`src/persistence/daily-entry-repository.ts`、`src/state/app-store.ts`、`src/features/journal/JournalPanel.tsx`、`src/features/journal/JournalPage.tsx` 及对应测试。
- IndexedDB 中现有 `dailyEntries` 记录保持可读；新保存记录写入标题。
- CSS 只需为标题输入复用现有纸页标题层级，避免改变页面布局和导航。
- 产品文档与架构 HTML 的日记数据流、持久化表格和验收状态需同步回写。

## 7. 风险、边界与回退

| 风险 | 发生条件 | 影响 | 缓解与回退 |
| --- | --- | --- | --- |
| 既有记录没有标题 | 用户升级后直接阅读旧记录 | 标题为空或显示异常 | 读取时按日期补齐“今天/日记”，保存时写入完整字段 |
| 标题校验过严 | 用户输入纯空格或超长标题 | 无法收笔 | 复用正文的错误反馈与保稿模式，标题长度设为独立常量并在测试中固定 |
| save API 调用方遗漏新参数 | 单元测试替身或其他调用方仍按旧签名调用 | 类型/运行时失败 | 全量 `rg` 调用检查、更新所有 repository mock 与测试 |
| 标题与正文不同步 | 保存一方失败或离开页面 | 用户看到旧标题/新正文 | 标题和正文同一 repository 调用、同一 dirty guard；失败保留两者草稿 |
