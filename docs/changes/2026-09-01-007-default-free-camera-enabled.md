## 1. 给阅读者的结论

当前源码和产品文档都把自由视角定义为默认关闭；用户现在要求页面初始状态默认开启。实施后首次进入或刷新页面会直接启用受限 `OrbitControls`，右上角按钮显示“关闭自由视角”，固定机位按钮在自由模式下保持禁用。

这只改变初始会话状态，不改变自由视角的范围、相机限制、持久化策略或其他进入本子/贴纸流程时自动退出的行为。

## 2. 用户需求

用户要求：默认状态是开启自由旋转。

解释：`createAppStore()` 创建的新会话默认 `freeCameraEnabled=true`，`deskCameraTransitioning=false`；刷新仍重新按该默认值开启，不保存用户上次姿态。

## 3. 当前源码事实

- `src/state/app-store.ts` 的初始状态当前为 `freeCameraEnabled: false`、`deskCameraTransitioning: false`。
- `src/app/App.tsx` 根据 `freeCameraEnabled` 动态显示“开启自由视角”或“关闭自由视角”。
- `src/scene/DeskScene.tsx` 在 `freeCameraEnabled && notebookPhase === 'desk'` 时跳过固定机位过渡并挂载自由 `OrbitControls`。
- `src/state/app-store.ts` 在打开本子、贴纸工作台、选择贴纸等工作流切换时仍显式关闭自由视角；这些是业务流程退出行为，不应被本次默认值修改覆盖。
- 产品文档 `docs/product/mvp.md` 和历史变更记录仍写着“刷新页面恢复默认关闭”，与本次新需求冲突，实施后必须同步更新当前产品事实；旧历史记录保留为历史事实。
- `src/state/app-store.test.ts` 与 `src/app/App.test.tsx` 当前多个测试假设初始自由视角关闭，需要随批准方案调整。

## 4. 目标与非目标

### 4.1 目标

- 新会话与刷新后的页面默认开启自由视角。
- 初始按钮标签和 `aria-pressed` 正确反映开启状态。
- 保留进入本子、贴纸工作台、选择贴纸和其他工作流时的自动退出。
- 保留会话内状态、不写入 localStorage 或 IndexedDB。

### 4.2 非目标

- 不扩大 OrbitControls 的旋转范围，不增加自由走动、平移或缩放。
- 不保存用户上次自由视角状态或相机姿态。
- 不改变固定机位按钮和其他右上角控件的业务逻辑。

## 5. 方案说明

最小实现是把 `createAppStore()` 的初始 `freeCameraEnabled` 改为 `true`，并更新受影响测试与当前产品文档。所有业务流程中的显式 `freeCameraEnabled: false` 保持不变，确保打开本子、贴纸等流程仍会退出自由视角。

## 6. 预计改动与影响评估

- `src/state/app-store.ts`：修改新会话默认值。
- `src/state/app-store.test.ts`、`src/app/App.test.tsx`：将初始状态、按钮标签和相关流程断言调整为默认开启。
- `docs/product/mvp.md`：更新自由视角当前事实和刷新后的默认行为。
- `docs/changes/2026-09-01-007-default-free-camera-enabled.md`：回写实施与验证结果。

### 6.1 核心数据结构变化

无结构变化；仅改变 `AppState.freeCameraEnabled` 的初始默认值，从 `false` 改为 `true`。

### 6.2 上下游与跨模块影响

初始场景渲染直接使用自由相机；右上角按钮初始标签变为“关闭自由视角”；固定机位按钮初始禁用。工作流退出和刷新后的非持久化语义按新默认值更新。
