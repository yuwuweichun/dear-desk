## 1. 给阅读者的结论

实施前的半张刚性 DOM 纸片只能绕书脊做 CSS 3D 旋转，不能形成阅读器常见的连续卷页。现已按批准方案用固定版本 `page-flip@2.0.7` 替换该渲染层：一次翻页准备当前与目标日期共四张只读页面快照，核心库只在独立容器内计算移动折线、裁切、正反面和动态阴影；真实 React 页面、日期加载和业务状态协议保持原有所有权。

原型证明核心库路线可以可靠隔离，因此没有转入自研完整折页算法，也没有采用 `react-pageflip` 或 npm `turn.js`。适配层额外补齐响应式时长归一化和上游递归动画帧清理；桌面、移动端、reduced-motion 和连续资源释放均已验证。实现没有引入物理引擎或第二个 WebGL Canvas，并已通过用户对视觉效果和节奏的验收。

## 3. 实施前源码事实与当前差异

以下前七项记录问题诊断时的实施前基线，用于解释为什么本任务需要替换渲染模型；它们不再代表当前工作区实现。

- `JournalPanel` 在目标日期加载完成、状态进入 `turning` 后挂载 `PageTurnSheet`。
- `PageTurnSheet` 是不包含实际页面内容的半宽绝对定位 DOM，只有空的正反面。
- CSS 动画使用固定 `transform-origin` 和 `rotateY` 为主的刚性变换；`rotateX`、`translateZ` 和 `brightness` 只能改变整片纸的姿态和亮度，不能产生沿纸面连续变化的曲率。
- 动画结束后 `settleJournalTurn()` 才提交 `journalCursor`，因此底层真实内容在整个动画期间保持旧日期。
- 产品文档当前明确不引入真实纸张动力学、软体物理引擎或第二个 WebGL Canvas；并未禁止使用 Canvas 2D、SVG 或 DOM 分片。
- 桌面 `1920 x 1050` 实测中，静止时翻页层与单页同为 `576 x 766.5px`，起止边界准确对齐；动画约 367ms 时，`rotateX` 令顶部偏移约 `-0.2px`、高度减少约 `1px`。这会造成细小裁切抖动，但不是截图中大面积错位的主因。
- 视觉实测显示，翻到一半时空白背面成为覆盖半本书的灰褐色刚性矩形，边界始终是一条直线；底层仍显示旧日期内容。动画结束后左右真实页面才同时替换为目标日期，因此存在结构性的内容跳变。
- `.page-turn-face` 的固定渐变、`mix-blend-mode: multiply`、整片 `brightness(0.68)` 和 10px 纸口条纹一起把背面压成深灰纸板；阴影随纸片自身旋转，不是沿折线投到静止页面上的接触阴影。
- 当前自动测试覆盖方向、重入锁、游标结算和翻页层无日期文字，但不覆盖中间帧几何、源/目标内容分层或视觉连续性。
- **当前源码事实**：上述空白刚性半页、固定 `rotateY` 关键帧和纸板亮度样式已经删除；`PageTurnSheet` 现在渲染四张实际页面快照并通过隔离的 `page-flip` 实例完成按钮自动翻页，测试同时覆盖快照配对、响应式时长和递归帧清理。

## 4. 目标与非目标

### 4.1 目标

- 解释当前效果僵硬与错位的根因。
- 比较可实现阅读器式卷页的原生和第三方路线。
- 给出推荐路线、预计复杂度、风险和可验收标准。
- 用固定版本核心库替换刚性半页渲染，同时保持真实 React 页面、业务状态协议与单 Canvas 边界不变。
- 在桌面、移动端与减少动态效果下验证双向按钮翻页、内容连续性和资源清理。

### 4.2 非目标

- 不引入物理引擎或第二个 WebGL Canvas。
- 不改变日记日期加载、书写保护、持久化和页面内容结构。
- 首期不开放纸角拖拽、触摸滑动、整页点击或悬停卷角。
- 不采用 `react-pageflip`、npm `turn.js` 或把真实可交互 React 节点交给第三方库管理。

## 5. 方案说明

阅读器式仿真翻页的核心不是完整纸张物理，而是二维折页几何：根据被拉动的纸角计算折线、活动页多边形、背面反射变换、下层露出区域和沿折线变化的阴影。十多年前的阅读器已经普遍使用这类近似算法，所以不需要布料模拟；但它仍然需要正确的页面分层和内容快照，不能由一个 `rotateY` 平面替代。

对 Dear Desk，一次日期切换应至少同时准备四个视觉层：当前静止页、当前活动页正面、目标页背面、目标静止页。目标静止页要在翻动过程中逐渐露出，活动页背面要承载下一跨页的左页视觉；只有可交互的真实 DOM 在动画结束后接管。这样才能保留现有 `loading -> turning -> idle` 协议，同时消除结束瞬间的整本内容跳变。

| 路线 | 能达到的效果 | 点击自动翻页复杂度 | 跟手拖拽复杂度 | 结论 |
| --- | --- | --- | --- | --- |
| 调整现有单片 CSS 3D | 更柔和的硬纸板翻转；不能形成移动折线和卷角 | 约 0.5-1 天 | 不适合 | 只适合作为低成本止血，不作为目标方案 |
| 原生 DOM + TypeScript 折页几何 + `clip-path` | 接近常见网页阅读器；支持正反面、斜向折线和动态阴影 | 约 3-5 天 | 约 6-10 天 | 可控、无新依赖，但几何和跨浏览器测试由项目长期承担 |
| SVG + `foreignObject`/滤镜 | 可精细控制裁切和阴影 | 约 4-7 天 | 约 7-12 天 | `foreignObject`、字体和移动浏览器兼容成本偏高；适合辅助阴影，不适合作为首选页面承载层 |
| Canvas 2D | 位图页卷动稳定，适合纯图片/PDF 阅读器 | 约 5-8 天 | 约 8-15 天 | 当前正文、表单和贴纸是 DOM；需要重复排版或不可靠地栅格化 DOM，不推荐 |
| 现有 Three.js 场景内纸张网格 | 可做真正曲面与光照 | 约 7-15 天 | 更高 | 必须把 DOM 栅格化成纹理并处理 DOM/WebGL 遮挡，违反当前职责分工，不推荐 |
| `page-flip` 核心库 | 内置二维折页几何、HTML 页面、动态阴影、点击/拖拽和响应式 | 隔离原型约 1-2 天，完整接入约 3-6 天 | 已提供，仍需业务集成验收 | 首选验证路线；固定版本、直接接核心，不使用 React 包装层 |

复杂度是基于当前代码结构的工程估算，不含重新设计日记页面。只做按钮触发的自动翻页明显比纸角跟手拖拽更容易稳定。

第三方核对事实：npm 的 `page-flip@2.0.7` 为 MIT、无运行依赖，发布 bundle 约 44KB，最后发布于 2022-05；源码通过折页交点、多边形裁切、DOM 临时副本和动态阴影渲染软页。`react-pageflip@2.0.3` 约 3.4KB，但开发基线是 React 17、依赖写成 `page-flip: latest`、没有明确 React peer 约束，并通过克隆 children、注入 ref 和直接更新 DOM 接管页面。Dear Desk 使用 React 19，直接采用该包装层会放大版本漂移和 DOM 所有权风险。

`turn.js` 也能实现经典双页卷页、动态渐变和按钮调用，但 npm 的 `turn.js@1.0.5` 不是原作者的正式发行，而是 `igghera/turn.js` 为 npm/Webpack 制作的第三方 fork。它的 README 明确说明基于旧版 `blasten/turn.js`，并因 jQuery 3.x 会破坏翻页而固定依赖 `jquery@1.12.0`；运行代码仍使用 CommonJS、jQuery data、全局 document 事件、旧 vendor prefix 与直接 DOM 包裹/重排。包元数据声明 MIT，但包内 `license.txt` 是 Turn.js 第三版的非商业许可证，明确限制只能用于个人利益且不得用于商业或营利目的，二者冲突。基于来源、许可证、依赖年代和 React DOM 所有权风险，本任务不采用 npm `turn.js`；即使当前项目用途非商业，也不能把冲突元数据当作清晰授权。

## 6. 预计改动与影响评估

实际改动固定引入 `page-flip@2.0.7`，由 `JournalPanel` 向 `PageTurnSheet` 同时提供当前与目标日期快照；后者命令式创建四张不可交互的 DOM 页面，并在独立容器内驱动核心库。旧的刚性半页关键帧和纸板亮度样式已删除。现有 `loading -> turning -> idle`、目标页预读、重入锁、dirty guard 与 `settleJournalTurn()` 接口均未改变。

### 6.1 核心数据结构变化

持久化 schema、Zustand store 字段和公共业务协议没有变化。渲染层新增 `JournalTurnSnapshot`，包含日期、正文、是否今天和贴纸数组；它只在一次动画挂载期间存在。库实例、四张页面节点、贴纸对象 URL、全局事件和受管 `requestAnimationFrame` 循环均由 `PageTurnSheet` 所有并在卸载时释放。

### 6.2 上下游与跨模块影响

- 上游：日期页按需加载和按钮重入锁。
- 当前渲染：左页贴纸、右页正文及编辑态 DOM。
- 下游：动画完成时提交游标、减少动态效果、桌面与移动端布局。
- 工程：依赖体积、React 兼容、SSR 非适用、浏览器合成性能和可访问性。

## 7. 风险、边界与回退

| 风险 | 发生条件 | 影响 | 缓解与回退 |
| --- | --- | --- | --- |
| 只改关键帧仍达不到卷页效果 | 继续使用单块刚性半页 | 视觉仍像翻硬卡片 | 将 CSS 调整限定为低成本修补，不作为目标方案 |
| 页面内容与动画纸面不同步 | 动画层继续使用空纸片 | 中途出现跳变、重影或语义错位 | 使用当前页/目标页快照参与动画 |
| 第三方库与现有双页布局冲突 | 库接管尺寸、DOM 和手势 | 集成成本超过自研渲染层 | 直接集成 `page-flip` 核心，关闭库的整页点击/鼠标手势，只由现有按钮驱动；先做隔离原型 |
| 移动端性能不足 | 高频重绘或分片过多 | 掉帧、发热 | 限制像素比、按需动画、保留 reduced-motion 回退 |
| React 与第三方同时修改同一节点 | React 重渲染时库克隆或覆盖页面样式 | 页面丢失、事件重复或卸载泄漏 | 给库独立的纯展示 DOM 快照；真实交互 DOM 不交给库；卸载时显式销毁 |
| 依赖长期无人维护 | 浏览器行为或 React 集成变化 | 后续升级风险 | 固定 `2.0.7`，记录来源与许可证；只依赖核心算法 API，保留回退到原生折页渲染层的边界 |
| 误用 npm `turn.js` fork | 只依据 package.json 的 MIT 字段安装 | 引入 jQuery 1.12、模糊授权和旧 DOM 事件模型 | 以包内许可证和源码为准；本任务明确不采用该包 |

## 11. 实施记录

已固定安装 `page-flip@2.0.7`，未引入 `react-pageflip`、jQuery、物理引擎或第二个 Canvas。`PageTurnSheet` 现在为当前日期和目标日期分别生成贴纸左页与正文右页，按方向排序后交给核心库；页面包含原有日期页眉、标题、正文和贴纸视觉，不再使用空白纸片。下一页从当前跨页开始调用 `flipNext('bottom')`，上一页从目标跨页之后开始调用 `flipPrev('bottom')`，只由既有按钮触发。

实现关闭库的纸角提示、页面点击和手势命中，真实 React DOM 始终留在动画层下方。`page-flip-runtime.ts` 解决两个上游生命周期问题：根据实际页宽补偿上游按路径像素缩短动画的行为，使桌面和移动端都接近 720ms；捕获上游未在 `destroy()` 中停止的递归 `requestAnimationFrame`，让 React 卸载时可以取消。清理还包括起始帧、完成兜底计时、库事件、当前动画、全局输入/resize 监听和贴纸对象 URL。

reduced-motion 不创建 StPageFlip 实例，只用四张快照执行 120ms 目标跨页淡入。库初始化或完成事件异常时保留静态回退和 1080ms 完成兜底，不让 store 永久停在 `turning`。实际修改覆盖依赖清单、翻页组件、运行时适配、样式、组件测试、产品/架构/入口文档与第三方声明；持久化数据、store 结构和公共业务接口未变。
