## 1. 给阅读者的结论

当前场景颜色面板与音频、字体菜单没有采用同一种展开关系：它被定位在页面右上角，而且打开时会替换掉整个右上工具栈，所以视觉上覆盖了按钮，也让其他功能入口暂时消失。

建议让颜色面板从调色板按钮左侧展开，并在面板打开期间继续显示调色板、字体和自由视角按钮。桌面和窄屏都为右侧按钮列保留空间；颜色列表仍在面板内部滚动，不改变调色功能和数据行为。

首次实施已解决按钮遮挡，但验收发现颜色、字体和音频面板可以同时打开。修订现已让三者共享唯一“当前打开面板”，打开任意一个都会关闭另两个，按钮保留可见但面板内容严格互斥。

## 2. 用户需求

- 用户原始要求：其他面板都在功能按钮侧边打开、不遮盖按钮；场景颜色面板直接覆盖按钮，表现不统一，需要调整。
- Codex 解释：颜色面板应与右上音频面板、内容字体菜单采用一致的“面板在左、按钮列在右”空间关系；打开颜色面板时功能按钮不应消失或被遮住。
- 用户提供的三张截图分别展示了音频面板、字体菜单的期望关系和场景颜色面板的当前异常关系。
- 验收补充要求：所有向左打开的设置面板必须互斥，不能让场景颜色与音频或字体面板同时存在；Codex 解释为音频、场景颜色、内容字体三者全局最多打开一个。

## 4. 目标与非目标

### 4.1 目标

- 场景颜色面板在调色板按钮左侧展开，右侧工具按钮保持可见且不被面板覆盖。
- 桌面端和窄屏均维持“面板在左、按钮列在右”的一致关系。
- 面板高度受视口约束，九项颜色与命令仍可完整访问；内容过高时只滚动面板正文。
- 增加自动测试，防止以后再次用颜色面板替换整个工具栈。
- 音频、场景颜色和内容字体三个向左面板全局互斥；打开任意一个时另两个立即关闭，最多只渲染一个面板内容。

### 4.2 非目标

- 不改变九项颜色字段、默认颜色、实时材质更新、复制、重置或刷新恢复行为。
- 不把场景颜色改为持久化主题，不新增颜色预设或主题管理。
- 不重设计音频面板、字体菜单、按钮图标、工具排序或场景视觉。
- 不引入新的 WebGL Canvas、依赖、公共接口或数据迁移。

## 5. 方案说明

将 `SceneColorEditor` 与调色板按钮放入工具栈中的同一相对定位容器。工具栈无论颜色面板是否打开都保持渲染，颜色面板依据该容器向左偏移一个固定间距，行为与音频面板和字体菜单一致。

桌面端允许颜色面板维持现有最大宽度，并从调色板按钮的顶部对齐；最大高度按工具栈起点与视口底部的剩余空间计算。窄屏不再切换为全宽底部抽屉，而是在右侧按钮列左边使用剩余宽度，保留安全边距并让正文内部滚动。

修订方案由 `ProductApp` 统一持有 `openSettingsPanel: 'audio' | 'colors' | 'font' | null`。三个入口都变为受控组件：点击非当前入口时把它设为唯一打开项，点击当前入口、关闭按钮、Escape、外部指针或完成字体选择时清空。按钮始终保留，只有面板内容互斥；自由视角不是向左设置面板，不进入该枚举。

## 7. 风险、边界与回退

| 风险 | 发生条件 | 影响 | 缓解与回退 |
| --- | --- | --- | --- |
| 窄屏剩余宽度不足 | 视口接近移动端最小宽度且按钮列、边距和面板同时存在 | HEX 输入或标签挤压、横向溢出 | 使用 `min()` / `calc()` 限制面板宽度，保持稳定网格并在真实移动视口验收；必要时只压缩字段列间距，不覆盖按钮列 |
| 面板高度超出视口 | 小高度设备或浏览器工具栏占据空间 | 最后几项颜色或关闭命令不可达 | 以 `svh` 计算最大高度，固定头部，正文内部滚动 |
| 受控状态迁移遗漏关闭路径 | Escape、外部点击或字体选择仍调用旧本地 setter | 面板无法关闭或 `aria-expanded` 不同步 | 所有关闭路径统一调用 `onOpenChange(false)`，组件与 App 集成测试逐条覆盖 |
| 入口切换产生事件顺序竞争 | 当前面板的外部 pointerdown 与新入口 click 连续触发 | 新面板被旧关闭事件误清空 | 所有回调按目标值写入同一 `openSettingsPanel`，真实浏览器逐对切换验证最终唯一值 |
| DOM 组合调整破坏入口测试 | mock 组件或查询依赖原分支结构 | 测试失败但运行行为正确 | 更新测试到用户可见语义，保留工具顺序与 aria 查询 |
| 方案效果不符合预期 | 用户希望颜色面板仍从页面顶端开始而非与调色板顶部对齐 | 视觉位置需调整 | CSS 改动集中，可回退到原定位或仅调整垂直锚点，不影响颜色数据链路 |
