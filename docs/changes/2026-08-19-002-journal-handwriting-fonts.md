## 1. 给阅读者的结论

Dear Desk 当前的日记输入框和本子正文没有独立的字体选择能力：全局 CSS 首选 `Nunito`，中文继续回退到系统字体；日记纸面使用 Georgia/宋体回退。仓库没有内置 `Nunito` 或其他正文 Web Font，因此“CSS 首选字体”不等于每台设备实际渲染的字体。建议首版内置三种本地字体，覆盖“清晰手写楷书”“更有笔锋的行楷/毛笔感”“轻松糖果体”三种气质，并让书写输入与保存后的本子正文使用同一个选择结果。

候选资源可优先从 Google Fonts 的中文开源字体中核验：`LXGW WenKai`（霞鹜文楷，SIL OFL 1.1）、`Ma Shan Zheng`（马善政毛笔楷书，SIL OFL 1.1）和 `ZCOOL KuaiLe`（站酷快乐体，需按发布仓库/字体包随附许可证核验，常见发行标注为 Apache 2.0）。这三种字体的字形差异足以支撑首版选择；最终版本、文件子集、许可证文本和中文覆盖范围必须在实施前锁定并随仓库分发。

此前提到的猫啃网不作为本项目的首选来源：它是第三方索引，部分下载链路可能收费或授权说明不够直接。后续候选以 GitHub 上的作者/维护者仓库为准，并从仓库内的许可证文件和字体文件直接核验。

## 2. 用户需求

### 用户原始要求

1. 书写输入使用适合手写的字体。
2. 本子内容使用适合手写的字体。
3. 最初考虑三种字体：手写行楷、手写楷书、手写糖果体；也考虑支持用户自己上传字体文件。
4. 当前项目需要内置三种字体，并希望了解开源免费的手写字体资源。

### Codex 对需求的解释

- 首版先提供三种内置字体，不把用户上传字体作为本次必须实现的能力。
- 输入框与只读正文应共享同一个字体选择结果，避免用户书写时看到一种字体、保存后换成另一种字体。
- 字体只影响 DOM 文本的视觉投影，不改变 `DailyEntry` 的文本数据，也不进入 Three.js 场景或 IndexedDB。
- “行楷、楷书、糖果体”是视觉类别，不保证字体名称与类别完全对应；应以实际字形、中文覆盖、授权和文件体积共同验收。

## 3. 当前源码事实

- `src/styles.css` 的根字体栈使用 `Nunito, "Noto Sans SC", -apple-system, ...`；当前没有项目自带的字体文件目录或 `@font-face` 声明。因此设备没有安装 `Nunito` 时会继续回退，macOS 中文通常最终由苹方等系统字体渲染。
- `src/styles.css` 中 `.journal-form textarea` 与日记正文使用 `Georgia, "Songti SC", serif`。中文字符通常由 `Songti SC`（宋体）或系统 serif 回退渲染，当前不是手写字体。
- `src/features/journal/JournalPanel.tsx` 负责 textarea 书写会话；`src/features/journal/JournalPage.tsx` 负责正文页面投影。两者共同消费 `DailyEntry` 文本，但字体当前由全局 CSS 决定。
- `src/state/app-store.ts` 的 `saveJournalEntry(date, text)` 只保存日期和纯文本；`src/domain/daily-entry.ts` 的 `DailyEntry` 没有字体字段。
- `docs/product/mvp.md` 已批准普通文字记录，但明确排除复杂真实手写、钢笔物理和墨水模拟；字体替换属于 DOM 表现层增强，不等于新增手写引擎。
- 当前未发现字体选择、字体偏好持久化、用户字体上传、字体文件校验或字体许可证清单的实现。

## 4. 目标与非目标

### 4.1 目标

- 内置三种可商用边界清晰、可随应用分发的中文手写字体。
- 在书写输入和本子正文中提供字体选择，并确保选择结果在当前页面和重新打开后保持一致（持久化范围需审批）。
- 为字体资源记录来源、版本、许可证、文件格式、中文覆盖和预计体积。
- 保持日记正文数据结构为纯文本，兼容已有记录。

### 4.2 非目标

- 不实现笔迹轨迹、压力感应、墨水扩散、钢笔物理或 Canvas 手写。
- 不改变 `DailyEntry` 文本格式、日期索引、贴纸数据或 Three.js Canvas 所有权。
- 不在本次默认实现用户上传字体、字体管理器、字体删除或跨设备同步。
- 不把全局 HUD、贴纸 Forge 或品牌标题改成手写字体，除非后续单独批准。

## 5. 方案说明

建议采用“字体 token + 本地 `@font-face` + 统一日记字体选择”的方案：每个内置字体有稳定的 CSS family token；`JournalPanel` 的 textarea 与 `JournalPage` 的正文共同读取当前字体 token；选择偏好由应用设置层保存，具体持久化位置在审批时确定。字体文件从应用本地资源加载，不依赖外网字体服务。

候选资源（实施前必须从上游仓库核验许可证和版本）：

| 视觉定位 | 候选字体 | 常见许可证信息 | 选择理由 | 主要风险 |
| --- | --- | --- | --- | --- |
| 手写楷书、日常可读 | `LXGW WenKai` / 霞鹜文楷 | SIL Open Font License 1.1 | 中文覆盖广，长段正文可读性较好 | 文件体积可能较大，需选合适子集 |
| 行楷/毛笔笔锋 | `Ma Shan Zheng` / 马善政 | SIL Open Font License 1.1 | 笔锋明显，适合作为较有个性的记录字体 | 小字号和长段落可读性需实测 |
| 手写糖果体、轻松 | `ZCOOL KuaiLe` / 站酷快乐体 | 需以具体发布包许可证为准，常见发行标注 Apache 2.0 | 形态活泼，适合短句和轻量记录 | 中文覆盖、商业分发条款和版本需逐项核验 |

若候选字体在授权或中文覆盖验收中失败，备选方向是 `Zhi Mang Xing`（志莽行书，OFL 1.1）或 `Long Cang`（龙藏体，OFL 1.1）；它们更偏书法/签名，不建议直接替代正文默认字体。

## 6. 预计改动与影响评估

预计涉及：字体资源目录和许可证说明、日记字体 token/样式、日记输入与正文组件、字体选择控件、设置状态及其测试。用户上传字体若获批，将另立任务或在本记录中扩展执行清单，因为它会增加文件解析、校验、持久化和安全边界。

### 6.1 核心数据结构变化

建议新增非正文设置概念：

```ts
type JournalFontId = 'wen-kai' | 'ma-shan-zheng' | 'zcool-kuaile'
```

`DailyEntry`、IndexedDB `dailyEntries` 表和保存接口保持不变。若需要跨页面重开保持选择，新增的 `journalFontId` 应作为独立应用偏好保存，不嵌入每条日记；默认值和迁移策略待确认。

### 6.2 上下游与跨模块影响

- `JournalPanel` 的 textarea 与 `JournalPage` 的只读正文必须使用同一字体映射。
- 应用设置/持久化层可能新增一个轻量偏好键，但不能让字体偏好污染日记正文或贴纸模型。
- 字体文件会增加构建产物体积，需评估完整字体与子集化的取舍。
- 无障碍、字号、行高、中文标点换行和移动端宽度需要随字体分别验证。
- 若支持用户上传字体，字体文件的 Blob 生命周期、异常字体回退、来源可信度和 IndexedDB 体积上限都将成为额外跨模块影响。

## 7. 风险、边界与回退

| 风险 | 发生条件 | 影响 | 缓解与回退 |
| --- | --- | --- | --- |
| 许可证不适合分发 | 误把字体包或镜像站说明当作授权 | 法务和发布风险 | 锁定上游仓库、保存许可证原文和版本；不通过核验则替换候选 |
| 字体中文覆盖不足 | 生僻字、标点或用户姓名缺字 | 方框或混排回退 | 用产品示例文本和扩展字符集做覆盖测试，设置稳定回退栈 |
| 字体文件过大 | 直接打包完整 CJK 字体 | 首屏和构建体积增加 | 优先评估子集化；必要时按字体异步加载，但保持离线可用 |
| 手写字体难读 | 长段正文使用过于装饰的字体 | 记录阅读负担上升 | 默认使用可读字体；短句/装饰字体明确标注并提供快速切换 |
| 上传字体扩大范围 | 用户要求保存、删除或跨设备同步自定义字体 | 数据模型和安全边界变化 | 本记录先不实现；另立批准任务定义格式、大小、存储和回退 |

## 8. 验证与验收

- 自动测试：字体 token 映射、默认值、选择后 textarea/正文同步、已有纯文本记录不变、设置恢复和未知 token 回退。
- 构建与静态检查：字体资源路径、许可证文件、构建体积、`npm run lint`、测试、`npm run build`、`git diff --check` 和文档引用检查。
- 浏览器验收：使用 `ego-browser` 检查桌面 `1440 × 900` 与移动 `390 × 844`；分别输入中文长句、标点、数字和多行内容，验证书写态与阅读态字形、行高、换行、焦点和溢出。
- 持久化与恢复：若批准持久化字体偏好，刷新/重新打开本子后仍使用所选字体；切换浏览器或清除站点数据的行为按现有 local-first 边界记录。
- 成功标准：三种字体均能离线加载且许可证记录完整；输入框和本子正文一致；切换字体不修改正文内容；字体缺失时可读地回退，不阻塞记录保存。

## 9. 待确认项与决策

1. **三种字体是否采用建议组合？** 建议 `LXGW WenKai + Ma Shan Zheng + ZCOOL KuaiLe`；若更重视正文可读性，可把第三种替换为 `Zhi Mang Xing` 但其书法感更强。
2. **字体选择是否跨页面持久化？** 建议持久化为独立应用偏好；不建议写入每条 `DailyEntry`，以保持已有数据兼容。
3. **是否立即支持用户上传字体？** 建议首版不做，待内置字体验证后另立任务；上传会引入格式、大小、许可证、存储和安全校验。
4. **字体作用范围是什么？** 建议仅覆盖日记输入框和本子正文；贴纸文字、HUD 和其他 UI 继续使用现有字体体系。
5. **字体包与子集策略？** 需要在实施前确认是否接受构建体积增加，或允许按产品字符集生成子集；无论选择哪种策略，应用必须保持离线可用。

## 10. 最终批准方案

用户于 2026-08-19 先批准“开发阶段下载适用，不作为版本发布，获取云峰晶晶体放入项目中”，随后明确要求“现在添加更换字体的功能”，并以截图指定本子右侧阅读/编辑/书写工具列为入口区域。

最终执行清单：

1. 提供“纸页宋体、云峰晶晶体、玄冬楷书”三项；纸页宋体是现有回退字体，另外两项来自已获取的开发资源。
2. 字体入口只在编辑模式显示，位于右侧工具列“书写/收笔”按钮下方；点击后向本子方向弹出三项菜单，避免继续拉长竖向主按钮。
3. 选择作为全局日记偏好保存到 `localStorage`；输入框与阅读正文立即同步，刷新后恢复；`DailyEntry` 仍只保存纯文本。
4. 云峰晶晶体仅由 Vite 开发服务器从 `dev-assets/fonts/` 提供，生产构建不复制、不打包；生产环境若偏好指向该开发字体则回退纸页宋体。玄冬楷书沿用铭牌功能已存在的 `public/fonts/` 生产资源。
5. 不实现字体上传、不改变贴纸文字、HUD 或其他 UI 字体。
6. 补充组件/偏好测试，更新产品、架构和本文，运行 lint、测试、构建、文档检查，并使用 `ego-browser` 验证桌面和移动端。
